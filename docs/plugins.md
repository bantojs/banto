# 同梱プラグイン

同梱プラグインはコア本体にバンドルされ、管理画面の **プラグイン** ページで有効/無効を切り替えます（再デプロイ不要）。
有効にすると **連携（hooks）** の送信先として並び、設定・無効化・削除はそこで行います。
API キー等のシークレットは DB に置かず、Cloudflare の **変数とシークレット**（Workers & Pages → banto → 設定）に
種類「シークレット」で登録します（CLAUDE.md §1-5）。以下の `npx wrangler secret put ...` は開発者向けの同じ操作です。

同梱プラグイン一覧: Stripe 決済（カード）、KOMOJU 決済、Amazon Pay、メール通知、LINE 通知。

## Stripe 決済（カード）

クレジットカード決済。設定手順は [docs/setup.md の「5. 決済（Stripe）をつなぐ」](setup.md#5-決済stripeをつなぐ) を参照してください。
必要なシークレット: `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`。

外部プラグイン（自分でホストするもの）の作り方は [docs/hooks.md](hooks.md) を参照してください。

## メール通知

注文確認（`order.paid`）と発送通知（`order.shipped`）を購入者に送ります。運営者にも控えを送れます。お店で試着のお知らせもここから送ります。
会員のログインのコード・メンバーの招待のメールも、このプラグインの送信元から送ります。
購入者の連絡先は hooks のペイロードには載せず、同梱プラグインが DB から直接読みます（外部プラグインには渡りません）。

送り手は Cloudflare の変数 `MAIL_TRANSPORT` でデプロイ全体に 1 つ選びます（[docs/email.md §1](email.md)）:
**Resend**（既定、`RESEND_API_KEY`）/ **自分の SMTP サーバー・SMTP リレー**（`SMTP_HOST` ほか。レンタルサーバーや VPS のメールアカウント）/ **SendGrid**（`SENDGRID_API_KEY`）/ **Amazon SES**（`SES_REGION` と鍵）。

1. 送り手で自分のドメインを認証します（SPF / DKIM。DNS に数件追加）。
2. Cloudflare の変数とシークレットに、送り手の値を追加します（プラグインの画面に、今の送り手と足りない名前が出ます）。
3. 管理画面 → ショップ設定 → プラグイン → **メール通知** を有効にし、送信元（認証したドメインのアドレス）を設定します。
4. ショップ設定の「基本と法定表記」で連絡先のメールアドレスを入れておくと、返信先と運営者控えに使われます。

送信は Cron（5 分おき）で行われ、失敗すると最大 5 回再送されます（Resend には再送しても二重に送らない鍵を付けます）。Resend の無料枠（月 3,000 通）で小規模なショップには十分です。

### 注文のメールを外部プラグインに任せる

注文のメールを外部プラグイン（MA・CRM のメール配信など）から送りたいときは、**メール通知を ON のまま**、設定の次の欄に印を付けます（どちらも既定は送る）。メール通知を OFF にすると、会員のログインのコード・招待・お問い合わせなどのメールの送信元も無くなって止まるので、OFF にはしないでください。

- **注文のメールを送らない（外部プラグインに任せる。運営者への控えも止まります）**: 受付（代金引換の受付を含む）・入金・発送のメールと運営者への控えを送りません。「運営者にも控えを送る」に印があっても、注文の控えは送りません（控えが要るなら外部プラグインから送ります）。
- **お店で試着のお客様あてのお知らせを送らない（店舗あては送ります）**: お店で試着の受付・取り置き・取り消しのお客様あてのお知らせ（と運営者への控え）を送りません。店舗あての申し込みのお知らせは今までどおり送ります（店舗のアドレスは外部プラグインには渡らないため）。

「注文のメールを送らない」に印を付けると、運営者への注文の控えも止まります。新しい注文を運営者に知らせたいときは、同梱の「LINE 通知」（`line_notify`、運営者の LINE に届きます）を ON にするか、外部プラグインから送ってください。AI 用 API はショップの連絡先メールアドレス（`settings.contact_email`）を返さないので、運営者のアドレスは外部プラグインの側の設定で受け取るようにします。

印を付けても hooks（`order.created`・`order.paid`・`order.shipped`・`tryon.requested`・`tryon.updated`）は外部プラグインに今までどおり届きます。外部プラグインは注文 ID で AI 用 API（`GET /api/v1/orders/{id}`、宛名とメールは `orders:contact`。住所も要るなら `orders:address` も（両方で `orders:pii` と同じ形、社内のメモは除く）から中身を引いて送ります。発送のメールに書くお問い合わせ番号は、注文の `tracking`（0172、`orders:read`）にあります（[docs/ai-access.md](ai-access.md)）。

送信元ドメインの認証（SPF / DKIM）と Supabase の認証メールの設定は [docs/email.md](email.md) を参照してください。未設定だと迷惑メールに入ります。

## LINE 通知

注文が入ったとき・キャンセルされたとき・在庫が閾値以下になったときに、LINE Messaging API で運営者に push します。
購入者の個人情報（氏名・住所・メール）は送りません。
在庫の閾値は、棚卸しや取り込みで一度に多くの SKU が下回ることがあるので、同じ回の配信の分を 1 通にまとめます（20 件まで並べ、残りは「ほか N 件」）。公式アカウントの無料の通数を在庫の知らせで使い切らないためです。

1. [LINE Developers](https://developers.line.biz/) で Messaging API チャネルを作成し、「Messaging API 設定」で **チャネルアクセストークン（長期）** を発行します。
2. 「チャネル基本設定」の **あなたのユーザー ID**（`U` で始まる）を控え、そのチャネル（公式アカウント）を友だち追加します。
3. 管理画面 → プラグイン →「LINE 公式アカウント」にチャネルアクセストークンを貼ります（ショップごと、暗号化して保存。docs/line.md）。ショップが 1 つだけなら、Cloudflare の変数とシークレットに種類「シークレット」で `LINE_CHANNEL_ACCESS_TOKEN` を追加しても構いません。

```bash
# 開発者向け
npx wrangler secret put LINE_CHANNEL_ACCESS_TOKEN
```

4. 管理画面 → ショップ設定 → プラグイン → **LINE 通知** を有効にし、送信先のユーザー ID を保存します。

配信は Cron（5 分おき）で行われ、失敗すると最大 5 回再送されます。結果は「連携」ページの配信履歴に出ます。

## KOMOJU 決済

コンビニ払い・銀行振込・PayPay などを [KOMOJU](https://komoju.com/) のホスト型決済ページで受け付けます。Stripe と併用できます。
KOMOJU の決済ページは配送先を集めないため、Banto 側でお届け先を入力してから KOMOJU へ転送します。

1. KOMOJU ダッシュボードの **設定 → API キー** から **シークレットキー**（`sk_...`）を控えます。
2. **設定 → Webhook** でエンドポイントを追加します。
   - URL: `https://<Worker の URL>/webhooks/komoju`
   - イベント: `payment.captured`, `payment.expired`, `payment.cancelled`
   - 表示される **シークレット** を控えます
3. Cloudflare の変数とシークレットに、種類「シークレット」で `KOMOJU_SECRET_KEY`（シークレットキー）と `KOMOJU_WEBHOOK_SECRET`（Webhook のシークレット）を追加します。

```bash
# 開発者向け
npx wrangler secret put KOMOJU_SECRET_KEY
npx wrangler secret put KOMOJU_WEBHOOK_SECRET
```

4. 管理画面 → ショップ設定 → プラグイン → **KOMOJU 決済** を有効にします。
   - **受け付ける支払い方法**: `konbini,bank_transfer,paypay` のようにカンマ区切り（空なら KOMOJU 側の既定）
   - **在庫を確保しておく時間**: 既定 72 時間。コンビニ払いは支払いまで日数がかかるため、Stripe（30 分）より長く取ります。期限内に支払われなければ在庫は戻ります。期限後に支払われた場合は在庫があれば確定し、無ければ自動で返金します。

注文は **Webhook（`payment.captured`）を受信したときにだけ** 確定します。KOMOJU のテストモードでは、ダッシュボードから支払いを「完了」にして Webhook を発火できます。

### KOMOJU のお支払いに戻る（0180）

お客様が KOMOJU の決済ページで手続きをせずにお店へ戻ってきても、後からお支払いに戻れます。

- 完了画面（`/checkout/done`）に「お支払いに進む」「このお申し込みを取りやめる」が出ます。会員なら会員ページにも「お支払いが済んでいないお申し込み」として並びます（お支払いの期限まで）。
- 「お支払いに進む」は、押したときに KOMOJU で決済ページの状態を確かめます。手続き前なら同じ決済ページへ戻します。KOMOJU の決済ページは作ってから最長 24 時間で期限が切れるので、切れていれば同じ予約・同じ金額・同じ支払いの種類で作り直します（予約の在庫と期限はそのまま）。コンビニ・銀行振込の手続きが済んでいれば「KOMOJU から届いたメールの案内でお支払いください」と出します。
- 「取りやめる」は、KOMOJU の決済ページ（手続き済みならお支払い待ちの支払い）を先に取り消し、取り消せたときだけ在庫を戻します（後から払えないように）。支払いが済んでいれば取り消さず、確定を待ちます。
- Banto が予約に残すのは決済ページの ID と支払いの種類だけで、URL や状態は押されたときに KOMOJU に聞き直します。
- 完了画面から戻れるのは、完了画面の照会トークンの期限（24 時間）までです。会員は会員ページから、お支払いの期限まで戻れます。
- 作り直す決済ページの期限は、予約の残りの時間までに縮めます（予約より長く払えるページを作らない）。残りが 10 分を切った予約は作り直しません。
- 万一、作り直す前の決済ページでも払われて 1 つの予約に 2 回の支払いが届いたら、2 回目は自動で返金します。
- 翌日の「お支払いのお願い」（メール・LINE）を送れます。ショップ設定 → お知らせの文面 → 「お支払いのお願い（KOMOJU）」で **送る** にします（既定は送らない、docs/notices.md「お支払いのお願い」）。リンクの先（`/checkout/resume`）でもお支払いに進む・取りやめるが選べ、お支払いの期限まで使えます。
- 当てる前（0180）は出ません。当てる前に作った予約は戻れません。

### 支払い方法ごとの手数料（0170）

コンビニ払いや銀行振込の手数料を **お客様に払っていただく** ときは、管理画面 → ショップ設定 → 支払い（またはプラグイン）→ **KOMOJU の支払い方法ごとの手数料** で、種類ごと（`konbini`・`bank_transfer`・`pay_easy` など、KOMOJU の種類の名前）に手数料を決めます。決め方は代金引換（docs/cod.md）と同じで、**一律** か **金額の段**（1 行に「この金額まで,手数料」、10 段まで。金額は商品の合計 + 送料 − 値引き）です。

- 決めると、カートと最終確認画面で KOMOJU を **種類ごとに** 選んでいただきます（例「コンビニ払い（KOMOJU・手数料 220 円）」「PayPay（KOMOJU）」）。並ぶのは「受け付ける支払い方法」に書いた種類で、その順です（手数料を決めていない種類は手数料なし）。受け付ける支払い方法が空のときは、手数料を決めた種類だけが並びます（KOMOJU の既定の「すべて」は、手数料のある種類を外せないため）。
- 最終確認画面の合計に **お支払い手数料** の行が入ります（特定商取引法の最終確認画面の表示）。手数料は値引きの対象外で、消費税は標準税率です。注文・注文メール・領収書・CSV にも同じ手数料が残ります。
- KOMOJU の決済ページは **選んだ種類だけ** で、金額は手数料込みです（決済ページで別の種類に選び直して手数料を外すことはできません）。
- 決済ページを作る前に、データベースが値引き後の金額でショップの決まりと同じかを確かめます。確定のときは、KOMOJU が知らせた支払いの種類が選んだ種類と違えば注文にせず返金します。
- 確定までのあいだ（コンビニ払いは数日）に手数料の決まりを変えても、確かめ済みの予約はそのときの手数料のまま確定します（払った人を返金にしない）。
- 決まりを 1 つも置かなければ、今までどおり「KOMOJU」1 つのボタンです。
- **KOMOJU のダッシュボード側でもお客様負担の手数料を設定しないでください**。両方に置くと、お客様が二重に払うことになるか、KOMOJU が受け取る額が Banto の計算と合わず注文にならない（返金になる）ことがあります。手数料は Banto の側だけで決めます。
- 管理画面は、受け付ける支払い方法が空のまま手数料を決めたとき（ほかの支払い方法がカートから消える）、受け付ける支払い方法に無い種類・知らない種類の名前に手数料を決めたときに警告を出します（保存はできます）。
- Stripe のコンビニ払いはこの仕組みの対象外です（Banto の Stripe の決済ページは 35 分で期限が切れ、支払いまで日数のかかるコンビニ払いには向かないため。コンビニ払いは KOMOJU で受けてください）。
- ヘッドレスは `provider` に `komoju:<種類>`（例 `komoju:konbini`）を送ります。手数料を決めたショップでは種類が要り、カートの `payments.komoju_methods` に並ぶ種類だけを受けます（docs/headless.md）。

### 1 デプロイ = 1 KOMOJU アカウント

KOMOJU の API キーは Workers Secret（デプロイ単位）なので、同じデプロイ内の全ショップで同じ KOMOJU アカウントに入金されます。
ショップごとに別のアカウントが必要な場合は、Stripe Connect（ショップごとに接続）を使ってください。

## Amazon Pay

お客様が Amazon アカウントに登録済みの支払い方法で払えるようにします（[Amazon Pay](https://pay.amazon.co.jp/) のホスト型の画面。日本・円）。Stripe・KOMOJU と併用できます。
お届け先は Banto 側で入力してから Amazon Pay へ移ります（Amazon Pay には「支払いだけ」を頼みます。カード番号は Banto を通りません）。

### 準備（Amazon Pay の Seller Central）

1. Amazon Pay の加盟店の登録を済ませ、**Seller Central** を開きます（最初は画面上部の切り替えで **テスト環境（Sandbox）** にしておくと安全です）。
2. **インテグレーション → インテグレーションセントラル** で、次を控えます。
   - **出品者 ID（Merchant ID）**
   - **ストア ID**（`amzn1.application-oa2-client.…`）
3. 同じ画面で **API キー（公開鍵 ID と秘密鍵）を作成** します。秘密鍵のファイル（`.pem`）がダウンロードされます。**公開鍵 ID**（`SANDBOX-…` / `LIVE-…` で始まるもの）を控えます。秘密鍵は再発行できないので、なくさないように保管してください。
4. ストアの設定の **JavaScript の許可するオリジン** に、お店の URL のオリジンを足します（例: `https://<Worker の URL>`、独自ドメインのショップは `https://shop.example.jp` も）。ここに無いオリジンでは支払いボタンが出ません。
5. **即時支払い通知（IPN）の設定** の **加盟店 URL** に `https://<Worker の URL>/webhooks/amazon-pay` を入れます（テスト環境と本番は別々に設定します）。

### 準備（Cloudflare）

Cloudflare の「変数とシークレット」に入れます。

| 名前 | 種類 | 値 |
| --- | --- | --- |
| `AMAZON_PAY_PRIVATE_KEY` | シークレット | 手順 3 の `.pem` ファイルの中身をそのまま貼る（`-----BEGIN PRIVATE KEY-----` から `-----END PRIVATE KEY-----` まで） |
| `AMAZON_PAY_PUBLIC_KEY_ID` | 変数 | 公開鍵 ID |
| `AMAZON_PAY_MERCHANT_ID` | 変数 | 出品者 ID |
| `AMAZON_PAY_STORE_ID` | 変数 | ストア ID |
| `AMAZON_PAY_SANDBOX` | 変数（任意） | 公開鍵 ID が `SANDBOX-` / `LIVE-` で始まらない古い鍵のときだけ。テスト環境なら `true` |

```bash
# 開発者向け
npx wrangler secret put AMAZON_PAY_PRIVATE_KEY < AmazonPay_privateKey.pem
```

管理画面 → ショップ設定 → プラグイン → **Amazon Pay** を有効にすると、カートに「Amazon Pay で支払う」が出ます（足りない設定があるあいだは出ません）。
本番に切り替えるときは、Seller Central の本番環境で同じ手順（API キー・許可するオリジン・IPN）をやり直し、`LIVE-` の公開鍵 ID と秘密鍵に入れ替えます。

### 流れと確定のしかた

1. カート → お届け先 → 最終確認（特商法の表示）→ 在庫を予約 → **Banto の中継ページ**（Amazon Pay のボタン）
2. ボタンを押すと Amazon Pay の画面へ。支払い方法を選んで「支払う」
3. お店に戻ったとき、Banto が **Amazon Pay の API で状態と金額を確かめてから** 支払いを確定し（`CompleteCheckoutSession`）、売上が確定していれば注文を確定します
4. 戻る前にブラウザを閉じても、Amazon Pay の **IPN** が届けば同じ確かめ方で注文を確定します

- 戻りの URL に付いてくる値は合図にしか使いません。どの予約か・いくらかは Banto が署名した券、支払ったかどうかは Amazon Pay の API の答えで決めます。IPN も、届いた中身ではなく API で引き直した Charge で判断します。
- IPN は Amazon SNS の封筒で届きます。Banto は次をすべて満たす通知だけを受け付け、どれかが欠けると Amazon Pay の API を呼ぶ前に断ります（403）。
  - SNS の署名が合う（署名の版 1・2、証明書は `https://sns.<リージョン>.amazonaws.com/…pem` から取って 1 日覚える、72 時間より古い通知は断る）
  - 通知を送った SNS のトピック（`TopicArn`）を、デプロイの設定で許している（下の「IPN を受け付ける（トピックの許可）」。許す設定があれば、許していないトピックの通知は署名を確かめる前に断ります）
  - 署名の証明書が、トピックと同じリージョンの SNS のもの
  - 通知の `MerchantID` が `AMAZON_PAY_MERCHANT_ID` と同じ
- SNS の購読の確認・解除の通知は、確かめたうえで何もしません。Amazon Pay に無かった Charge の通知は受け取らずに 503 を返して Amazon Pay に再送させ（Amazon Pay は 1 時間ごとに最大 3 時間まで再送します）、同じ ID には 10 分のあいだ API を呼びません。
- 確定と返金の冪等の鍵は Amazon Pay の Charge ID です（戻りと IPN のどちらが先に届いても、注文も返金も 1 回だけ）。
- 在庫の予約は Stripe と同じ 40 分です。期限が切れた後に支払いが済んだときは、在庫があれば確定し、無ければ自動で返金します。
- Amazon Pay の画面で「戻る」を押すと、予約を戻してカートに戻ります。断られたときも予約を戻し、カートに「お支払いが完了しませんでした」と出します。
- Amazon Pay の画面へ移る中継ページだけが Amazon のスクリプト（`https://static-fe.payments-amazon.com/checkout.js`）を読みます。中継ページの CSP は、スクリプトを Banto と Amazon Pay の部品だけに絞り、フォームの送信先（`form-action`）に Amazon Pay の画面（`https://payments.amazon.co.jp` と Amazon の日本のドメイン）を許します。お店の画面・レジ（Liquid のテーマを含む）の CSP は変わりません。
- 注文のキャンセル（管理画面・AI 用 API）は、Amazon Pay で返金してから在庫を戻します（売り上げた額から返金済みの額を引いた額）。
- クーポンの条件「使える支払い方法」に **Amazon Pay** があります（マイグレーション `0130_amazon_pay` が要ります）。
- ヘッドレス: `provider: "amazon_pay"` で quote を作り、`checkout` の `payment_url`（Banto の中継ページ）へ購入者を移します。戻り先は `success_url` / `cancel_url` のとおりです（docs/headless.md）。

#### IPN を受け付ける（トピックの許可）

SNS の署名が合うことは「どこかの SNS のトピックから送られた」ことしか示しません（だれでも自分のトピックで署名つきの通知を作れます）。そこで、Amazon Pay の IPN を送るトピックをデプロイの設定で許します。Amazon Pay はそのトピックの一覧を公開していないので、Banto は決め打ちしません。

1. IPN の加盟店 URL を設定した後、Seller Central から IPN を試しに送るか、1 回支払います。**このデプロイが使う環境（テスト環境か本番。`AMAZON_PAY_SANDBOX` と鍵の ID の `SANDBOX-` / `LIVE-` のとおり）の IPN で** 確かめてください。
2. 設定が無いあいだ、IPN は断られ、Worker のログに `amazon-pay ipn: TopicArn not allowed: arn:aws:sns:…` と出ます（Cloudflare の画面 → Workers & Pages → あなたの Worker → ログ）。ログは Worker の実行の単位（isolate）ごとに 1 分 5 行までで、少なくとも 1 度は出ます。設定が無いあいだに確かめる通知の数も 1 分 30 通までに絞ります。
3. その ARN を、デプロイの変数 `AMAZON_PAY_IPN_TOPIC_ARNS` に入れます（カンマ区切り）。**入れるのは、このデプロイが使う環境のトピックだけ** にしてください（テスト環境の IPN の Charge は本番の鍵では見つからず、そのたびに 503 で Amazon Pay の再送（1 時間ごとに最大 3 時間）が起きます）。アカウント ID（ARN の 5 つ目の 12 桁）で許すときは `AMAZON_PAY_IPN_TOPIC_ACCOUNTS` に入れます（12 桁でないものは使わず、ログに 1 度知らせます）。

IPN は取りこぼしの保険です。設定が無くても、お客様がお店に戻ったときの確定（いつもの流れ）は変わりません。設定が無いと、戻る前にブラウザを閉じたときに注文が自動で確定せず、予約の期限が切れた後に支払いが残ることがあります（管理画面と Seller Central で確かめてください）。

### 1 デプロイ = 1 Amazon Pay アカウント

Amazon Pay の鍵はデプロイ単位なので、同じデプロイの全ショップで同じ Amazon Pay の加盟店に入金されます。
