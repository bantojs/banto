# ショップのページ（同梱モジュール）

「私たちについて」「よくある質問」「ギフトのご案内」のようなページを作り、お店の画面の `/<ショップ>/pages/<名前>`（独自ドメインでは `/pages/<名前>`）に出す同梱モジュールです（既定 OFF。0079_mod_pages の適用が必要）。

- 本文は**決まった書式**（見出し・太字・リンク・画像・表など。下の「書式」）で書きます。**HTML は書けません**（書いても文字のまま出ます）。
- 並びや見た目はテーマが決めます。既定のテーマはそのまま描き、Liquid のテーマでは `templates/page`（ページごとに `templates/page.<名前>` も選べます。docs/themes.md）で描きます。
- ヘッダーかフッターのメニューに出せます。
- 特定商取引法に基づく表記・プライバシーポリシー・返品ポリシーは今までどおりショップの設定です（このモジュールではありません。公開の条件だからです）。

## 1. 使い方

1. ショップ設定 → モジュール →「ページ」を ON にします。ショップの管理画面に「ページ」のタブが出ます。
2. 「新しいページ」を開くと、左に大きなタイトルと本文、右に「ページの設定」、上に「下書き保存・プレビュー・公開」のボタンが並びます（WordPress の編集の画面に近い形です）。
   - **画面は WordPress のブロックエディタと同じ 3 つの欄です**（JS が無いブラウザでは今までの 2 列）。上のバーの左に「戻る」・「＋」（ブロックの一覧）・「≡」（リスト表示）、右の端に設定の欄を開け閉めするボタン。中央は本文だけです。
     - **左: ブロックの一覧**。探す欄と図の並び。押すとカーソルの位置に入り、本文へドラッグすると置いた場所に入ります。
     - **左: リスト表示**。本文のブロックの並び（箇条書きの項目・引用の段落は下の段）。押すとそのブロックへ。ドラッグで並べ替え、Shift（続けて）か Ctrl・⌘（1 つずつ）を押しながら選ぶと、まとめて動かす・「まとめて削除」（Delete キーでも）ができます。
     - **右: 設定**（公開・アイキャッチ・URL・メニュー・画像・検索エンジン向け・リビジョン）。狭い画面では左右の欄は本文の上に重ねて開きます。開いていた欄は覚えます（この端末だけ）。
   - **本文はブロックで組み立てます**（WordPress のブロックエディタに寄せた操作）:
     - ブロックを入れる: 本文の上の「＋」、空の行の右に出る「＋」、ブロックとブロックのあいだにマウスを置くと出る「＋」。図の並んだ一覧から選ぶか、上の欄で探します。空の行で `/` を打っても一覧が出ます（続けて打つと絞り込み、矢印と Enter で選べます）。
     - 選んだブロックの上に道具が出ます: 種類を変える（段落・見出し・小見出し・箇条書き・番号付き・引用）、⠿ をつかんでドラッグ・「↑」「↓」で動かす、太字・斜体・リンク、商品とボタンのブロックは「設定」、「…」から前後に追加・複製・消す。文字を打っているあいだは隠れます。
     - 商品とボタンのブロックは押すと選べ、Delete で消せ、二度押しか Enter で設定を開けます。
     - Markdown に切り替えると、今までどおり書式のボタンが上に並びます。
   - 「ビジュアル」（見たまま）と「Markdown」（下の書式を直接書く）を切り替えられます。どちらで書いても、保存するのは同じ書式です。
   - **URL の名前**は、空のままならタイトルから作ります（`About Us` → `about-us`。英数字にならないタイトルは `page-xxxxxx`）。手で入れることもできます。
   - **プレビュー**は新しいタブで開き、保存はしません。公開中のショップでは、お店の画面の上（独自ドメインがあればそのドメイン）で本物のページと同じ処理・同じテーマ（Liquid のテーマを含む）で描きます。「見せる相手」のブロックは中身ごと出し、分析のタグは入れず、検索エンジンにも載せません。非公開のショップでは管理画面の中で既定のテーマで描きます（商品・ページ・記事のブロックの中身は公開するまで空です）。
   - **プレビューは編集に合わせて新しくなります**（メンテナの決定 2026-11-05）。「プレビュー」は同じタブを使い回し（押すたびにそのタブが最新になる）、開いているあいだは書き換えて少しするとそのタブも描き直します。タブを読み直しても最新を受け取り直し、読んでいた位置は残ります。
   - **お店の見た目の欄**: 上のバーの目のボタンで、編集の画面の横に同じプレビューを出せます（広い画面・スマホの幅を切り替え）。書き換えると少しして描き直します。
   - どちらもテーマはお店のオリジンの枠（sandbox）の中で描くので、テーマのスクリプトから管理画面には触れません（枠に入れてよいのは、券に結んだ管理画面のオリジンだけ）。テーマの CSS を編集の領域に直接当てることはしません。
     しくみ: 管理画面が下書きと 10 分の券（ショップと下書きの SHA-256 を結んだ署名）を作り、新しいタブからお店の画面の `POST /_preview/content` へ送ります。券で描けるのはその下書きだけで、何も書き換えません（管理画面のオリジンから届くので、このパスだけ Origin の検査をしません）。
   - **下書き保存**は公開しないで保存、**公開**で公開します。公開中のページは「更新」と「下書きに戻す」になります。Ctrl+S（Mac は ⌘S）で下書き保存（公開中なら更新）。保存していない変更があるときに画面を離れようとすると知らせます。
   - 画像は、ブロックの「画像」か右の「画像を置く」で選ぶと、ブラウザで縮めてから置き場に上げ、本文のその場所に入ります。
3. メニューに出すなら「メニュー」でヘッダーかフッターを選びます。並び順は小さい順です。
4. 組織のスタッフに任せるときは、組織の画面でショップごとに「ページ」の項目を割り当てます（ひな形「ページの担当」）。この項目だけの人は、商品・注文・会員の画面には入れません。

- URL の名前は英小文字・数字・ハイフンで 64 文字まで（先頭と末尾は英数字）。`legal`・`privacy`・`returns`・`shipping`・`cart`・`checkout`・`account`・`search`・`orders`・`inquiries` は使えません。
- 1 つのショップに 100 ページまで。Banto をホスティングして貸す構成では、プランの上限 `plan_limits.pages` でこの Banto 全体の数も決められます。
- 公開したページは、サイトマップ（`sitemap-pages.xml`）に載ります。
- 管理画面の JSON の書き出し（バックアップ）に入ります。空のショップへの復元（`restore_shop_data`）には入りません（ページは書き出しの JSON から手で戻してください）。

### 予約公開・ゴミ箱・リビジョン・アイキャッチ・メディアライブラリ（0080）

- **予約公開**: 右の「公開」の「公開する日時」に未来の日時を入れると、ボタンが「予約公開」になります。その時刻を過ぎるとお店の画面とメニューに出ます（判定はお客様が開いたときなので、決まった時刻に動く処理はありません。お店の画面の短いキャッシュの分だけ遅れて出ることがあります）。日時はデプロイの時間帯（`BANTO_TIMEZONE`）です。
- **ゴミ箱**: 「ゴミ箱へ移動」したページはお客様に見えず、一覧の「ゴミ箱」から戻せます。30 日たつと Cron が消します（運営者の画面から「完全に削除」はできません。0089 から）。ゴミ箱の中のページと同じ URL の名前で新しいページを作れます（そのときは、ゴミ箱のページは名前を変えるまで戻せません）。
- **リビジョン**: タイトルか本文を変えて保存するたびに、変える前の版を残します（新しい 20 件まで）。右の「リビジョン」から「この版に戻す」で戻せ、戻す前の内容もリビジョンに残ります。
- **アイキャッチ画像**: 右の「アイキャッチ画像」で選びます。既定のテーマはページの上と、SNS で共有したときの画像（og:image）に使います。Liquid のテーマには `page.image` と `page_image` で渡します（docs/themes.md）。
- **メディアライブラリ**: 置いた画像は一覧に残り、本文の画像のブロックとアイキャッチの両方から選び直せます。一覧は新しい順に 40 枚ずつ読み、下までスクロールすると続きを読みます（「さらに読み込む」でも）。一覧には、置いたときに管理画面が作った小さい画像（長辺 400px、0082）を並べます。
- **一覧**: すべて・公開中・予約・下書き・ゴミ箱のタブと、タイトルと URL の名前で探す欄があります。

## 2. 書式

```
## 見出し
### 小見出し

段落は空の行で分けます。
行の折り返しはそのまま改行になります。

**太字**　*斜体*　`コード`

[リンクの文字](https://example.com)　[送料について](/shipping)

![画像の説明](https://<画像の置き場>/pages/...)

- 箇条書き
- 箇条書き

1. 番号付き
2. 番号付き

> 引用

---

| 見出し | 見出し |
| --- | --- |
| 中身 | 中身 |
```

- `#` と `##` は同じ大きさの見出し、`###` は小見出し、`####` 以下はその下です（ページのタイトルが一番大きい見出しのため）。
- 見出しの中で改行するときは、行の末尾に `\` を書いて次の行に続けます（4 行まで。`## SPRING \` の次の行に `春の装い`）。見たままの編集では見出しの中で Shift + Enter です。文字の `\` で終わる見出しは `\\` と書きます。
- リンクは `https://`・`http://`・`/`（ショップの中）・`#`・`mailto:`・`tel:` から始まるものだけです。ほかは文字のまま出ます。外へのリンクには `rel="noopener"` が付きます。
- 画像は**ショップの画像の置き場のものだけ**です（外のサイトの画像は文字になります。お客様の閲覧を外に知らせないため）。編集の画面の「画像を置く」で置くと、本文に `![](URL)` が入ります。大きな画像はブラウザで長辺 1600px の WebP に縮めてから送ります。SVG は置けません。
- 記号をそのまま出したいときは前に `\` を付けます（`\*`）。
- ブログの記事（同梱モジュール「ブログ」、docs/blog.md）も同じ書式と同じ編集の画面です。
- 本文は 50,000 文字まで。表は 1 つにつき 30 列・500 行まで（超えた列は捨て、超えた行は出しません）。レイアウトの囲みは 4 段までで、それより深い囲みは行を外して中身だけを出します。本文から作る HTML が 1MB を超えるときは「本文が大きすぎます。」の段落だけになります（見る人全員の画面を重くしないため）。

### 商品を並べる・ボタン（1 行のブロック）

編集の画面ではブロックの一覧の「商品を並べる」「ボタン」から入れます。商品のブロックの設定では、タグはお店の公開中の商品にあるもの（件数つき）から選び、並ぶ商品の数がその場に出ます（0 件なら赤で知らせます。大文字・小文字の違いも別のタグです）。編集の画面の中の商品のブロックにも、並ぶ商品の見本が出ます。書式では次の 1 行です。

```
::: products category=tops tag=冬物 limit=8 layout=grid sort=new
::: button [すべての商品を見る](/products)
```

| 設定 | 値 | 既定 |
| --- | --- | --- |
| `category` | カテゴリーの URL の名前（子のカテゴリーの商品も含む） | すべて |
| `tag` | このタグを持つ商品だけ（空白を含むなら `tag="冬 物"`） | 絞らない |
| `limit` | 1〜24 | 8 |
| `layout` | `grid`（並べる）・`scroll`（横スクロール） | `grid` |
| `sort` | `new`（新しい順）・`updated`・`price_asc`・`price_desc`・`name` | `new` |
| `slugs` | 選んだ商品の URL の名前をカンマで区切って（24 個まで、0112）。**書いた順に**並べ、`category`・`tag`・`limit`・`sort` は使いません | 使わない（条件で選ぶ） |

- **記事の項目の商品を並べる**（`::: products from=@field:items layout=grid`、0117）: 記事の本文や記事のひな形で、開いている記事のその項目（商品の URL の名前）の商品を書いた順に並べます。ほかのページでは何も並べません。
- **似た商品を並べる**（`::: products related=@product limit=4`、メンテナの決定 2026-11-05）: 商品詳細のひな形に置くと、開いている商品と同じ主カテゴリーの商品を並べ、足りなければ同じタグ（最初のタグ）の商品で埋めます（その商品は除く）。Banto は閲覧の履歴を持たないので「いっしょに見られている」ではありません（それは行動の中継を使う外部プラグインの仕事、docs/event-relay.md）。商品の画面の外では何も並べません。編集の画面では「商品を並べる」の設定の「今の商品に似た商品」です。
- **選んだ商品を並べる**（`::: products slugs=coat,knit,tee layout=grid`、0112）: 「この着こなしの着用アイテム」のように、決まった商品を決まった順に並べます。見えない商品（非公開・会員限定で合わない人・無い URL の名前）は飛ばします。1 ページの選んだ商品のブロックは**まとめて問い合わせ 1 回**です。データベースの更新 `0112_product_pick` が当たるまでは空です。編集の画面では設定の「選んだ商品の URL の名前」に書きます。

- 並ぶのは**公開中の商品だけ**です（商品の一覧と同じ選び方とキャッシュ）。値段・在庫は商品の一覧と同じく、描いた時点のものです。
- 1 ページに **3 つまで**（4 つ目からは描きません）。1 つのブロックはお店の画面で問い合わせ 1 回（ブロックどうしは並列、2 回目からはキャッシュ）。
- 見た目はテーマが決めます。Liquid のテーマは `snippets/page-products.liquid` に `products`（一覧の形の商品）と `block`（`layout`・`limit`・`sort`・`category`・`tag`・`index`）を渡して描き、無ければ Banto の既定のカード（`ul.banto-products__list`）を出します（docs/themes.md）。
- ボタンのリンクの規則は本文のリンクと同じです。HTML は `<p class="banto-button"><a class="banto-button__link" href="…">文字</a></p>` で、見た目はテーマの CSS です。
- 文字として `:::` で始めたいときは前に `\` を付けます（`\:::`）。

### レイアウトのブロック（グループ・カラム・カバー・画像と文・ギャラリー・アコーディオン・スペーサー）

WordPress のよく使うブロックを、決まった書式のまま入れ子の囲みで書けます（メンテナの決定 2026-10-30）。編集の画面ではブロックの一覧の「デザイン」「メディア」「テキスト」から入れ、値は右の欄の「ブロックの設定」で選びます。

```
::::: group bg=subtle pad=l
:::: columns ratio=1-2
::: column
## 見出し
文
:::
::: column
::: products tag=NEW limit=4
:::
::::
:::::

:::: cover image=https://media.example.jp/pages/…/hero.webp height=l overlay=dark align=center
## ようこそ
::: button [商品を見る](/products)
::::

::: accordion icon=plus title="送料はいくらですか？"
全国一律 600 円です。
:::
```

- 囲みは「`::: 名前 値…`」の行で始まり、「`:::`」だけの行で**一番内側**を閉じます（`:` の数は問いません。編集の画面は読みやすいように外側ほど多く書きます）。閉じの無い囲みは本文の終わりまでです。
- **入れ子は 4 段まで**（カラムと列で 2 段）。それより深い囲みは、行を外して中身だけを描きます。編集の画面は 4 段を超える置き方をさせません。
- 値は**決まった選択肢だけ**で、色や大きさの実際の値はテーマが決めます（下の「テーマで決まる値」）。合わない値は既定になります。本文に CSS は入りません。
- 画像（カバーの背景・画像と文・ギャラリー）は本文の画像と同じく、ショップの画像の置き場のものだけです。

| 名前 | 値（太字が既定） | 中身 |
| --- | --- | --- |
| `group`（グループ） | `bg`=**none**/subtle/accent/dark、`pad`=none/s/**m**/l | ブロック |
| `columns`（カラム） | `ratio`=**1-1**/1-2/2-1/1-1-1/1-2-1/1-1-1-1（列の数と幅）、`valign`=**top**/center/bottom | `column` だけ（スマホでは縦に並ぶ） |
| `column`（列） | なし | ブロック |
| `cover`（カバー・ヒーロー） | `image`=URL、`height`=s/**m**/l/full、`overlay`=none/light/**dark**、`align`=left/**center**/right（左右）、`valign`=top/**center**/bottom（上下）、`focus`=top-left/top/top-right/left/**center**/right/bottom-left/bottom/bottom-right（画像のどこを残して見せるか。狭い画面で切り取られるとき） | ブロック（見出し・文・ボタン…） |
| `media`（画像と文） | `image`=URL、`alt="説明"`、`side`=**left**/right、`valign`=top/**center**/bottom | ブロック（文の側） |
| `gallery`（ギャラリー） | `cols`=2/**3**/4 | 画像の行だけ（`![説明](URL)`。60 枚まで） |
| `accordion`（アコーディオン・FAQ） | `title="質問"`、`icon`=**chevron**/plus/arrow/caret/none、`open`=**0**/1 | ブロック（答え）。`<details>` で、JS なしで開け閉め |
| `spacer`（スペーサー、1 行） | `size`=s/**m**/l/xl | なし |
| `text`（文字のスタイル） | `style`=テーマが決めた名前（リード文・小見出しなど。docs/themes.md「パターンとブロックのスタイル」） | 段落・見出し・リスト。余白も背景も足さず、テーマのスタイルを当てるだけ |

#### 記事を並べる（1 行のブロック）

同梱モジュール「ブログ」の記事を、ブログの並び順（既定は新しい順。docs/blog.md「並び順とフィード」）でカードにして並べます。編集の画面ではブロックの一覧の「記事を並べる」から入れ、ブログ・タグ・数・並べ方・並び順を選びます。

```
::: articles blog=news tag=セール limit=3 layout=grid
```

| 設定 | 値 | 既定 |
| --- | --- | --- |
| `blog` | ブログの URL の名前（必須） | — |
| `tag` | このタグの記事だけ。`@product` は描いている商品の URL の名前（商品詳細のひな形で使う。下） | 絞らない |
| `field:<キー>` | 記事の項目（0117、docs/blog.md「記事の項目」）がこの値の記事だけ。`@product` は描いている商品、`@article` は描いている記事の URL の名前。いくつも持てる項目は「含む」で比べます | 絞らない |
| `limit` | 1〜12 | 3 |
| `layout` | `grid`（カードを並べる）・`list`（縦に並べる） | `grid` |
| `sort` | `new`（新しい順）・`title`（題の順）・`manual`（ブログで手で並べた順）。0116 から | ブログの設定どおり |

- 公開中の記事だけ。1 ページに **2 つまで**。ブログのモジュールが OFF のショップでは何も出ません。
- **`tag=@product`**（メンテナの決定 2026-11-05）: 商品詳細のひな形（「ひな形の割り当て」）に置くと、開いている商品の URL の名前と同じタグの記事だけを並べます。たとえば着こなしの記事に、着ている商品の URL の名前（`wool-coat` など）をタグとして付けておけば、商品ごとに「この商品を着た着こなし」が出ます（ひな形は 1 つで足ります）。タグは文字のまま比べるので、URL の名前と同じ書き方（英小文字）で付けます。商品の画面の外（ふつうのページなど）では何も並べません。テーマの `snippets/page-articles` には置き換えた後のタグが渡ります。
- 見た目はテーマが決めます（`snippets/page-articles.liquid`、無ければ Banto の既定のカード。docs/themes.md）。

#### プラグインのブロック（1 行のブロック、0086）

外部プラグイン（レビューなど）がマニフェストで提案したブロックです。編集の画面ではブロックの一覧の「プラグイン」の組から選び、どの商品のデータを出すか（商品の URL の名前）と、プラグインの設定の欄を入れます。

```
::: app reviews reviews product=tee layout=list limit=5
```

- 1 ページに **2 つまで**。公開中の商品のデータだけ。プラグインを外すと何も出ません。
- 見た目はテーマが決めます（`snippets/app-<連携>-<ブロック>.liquid` → `snippets/app-<ブロック>.liquid`、無ければレビューだけ Banto の既定の見た目）。詳しくは docs/app-data.md §6。

#### テーマのスタイルとパターン

テーマがブロックのスタイルを決めていれば（docs/themes.md「パターンとブロックのスタイル」）、グループ・カラム・カバー・画像と文・ギャラリー・アコーディオンは右の欄の「スタイル」、ボタン・商品・記事のブロックは設定の画面で選べます。書式では `style=<名前>` です（`::: group style=framed`、`::: button style=outline [見る](/products)`）。ブロックの一覧の「パターン」「テーマのパターン」からは、よく使う組み合わせをまとめて入れられます。

#### テーマで決まる値

ブロックは class だけで描き（`banto-group banto-bg-subtle banto-pad-m` など）、並べ方の最小の CSS をレイアウトのブロックがあるページにだけ 1 回添えます（`src/pages/layout.ts` の `LAYOUT_CSS`）。色と大きさは CSS の変数で、テーマが決めます（無ければ既定）。

| 変数 | 使う所 | 既定 |
| --- | --- | --- |
| `--banto-bg-subtle` | 背景「薄い色」 | 薄い灰色 |
| `--banto-bg-accent` / `--banto-fg-accent` | 背景「アクセントの色」と文字 | `--accent`（既定のテーマのアクセントの色）/ 白 |
| `--banto-bg-dark` / `--banto-fg-dark` | 背景「濃い色」と文字・画像の無いカバー | 濃い灰色 / 白 |
| `--banto-pad-s` / `-m` / `-l` | 余白 | 1rem / 2rem / 3.5rem |
| `--banto-gap` | カラム・画像と文・ギャラリーのすき間 | 1.5rem（ギャラリーは .75rem） |
| `--banto-cover-s` / `-m` / `-l` | カバーの高さ | 16rem / 26rem / 36rem |
| `--banto-spacer-s` / `-m` / `-l` / `-xl` | スペーサー | 1.5rem / 3rem / 5rem / 8rem |
| `--banto-radius` / `--banto-line` | 角の丸み・アコーディオンの線 | .5rem / 薄い線 |

### グリッド・タブ

```text
:::: grid cols=3
1 つ目のブロック

2 つ目のブロック
::::

::::: tabs
:::: tab title="送料"
全国一律 600 円です。
::::
:::: tab title="返品"
到着から 7 日以内に。
::::
:::::
```

- **グリッド**は、中のブロック（段落・画像・カードなど）を 1 つずつ升目に並べます。列の数は 2〜6、狭い画面では 2 列までです（2 列のグリッドは 1 列に）。
- **タブ**は、中の「タブ」（題つき）を切り替えて見せます。8 つまで。切り替えは CSS だけで、JS は使いません。見たままの編集では、右の設定の「タブの数」で足し引きします。タブの外の行は描きません。

### お店のブロック（1 行のブロック）

| `::: search placeholder="商品を探す"` | 商品の検索の欄（`/products?q=…` へ） |

| `::: card page=about` ／ `::: card article=news/hello` | ページか記事を 1 つ、カード（題・アイキャッチ・抜粋）で |
| `::: product slug=tee show=image,name,price,cart,buy` | 1 つの商品。`show` に出す項目（`image`・`name`・`price`・`options`（選択肢の値と見本。押すとその SKU を選んだ商品ページへ。0115）・`sku`・`tags`・`description`・`cart`（カートに入れる）・`buy`（今すぐ買う）・`field:<key>`（商品の独自項目。公開の項目だけ。画像の項目は `<img>`。メンテナの決定 2026-11-05））。省けば画像・名前・価格・カートに入れる |

| `::: toc levels=3 title="この記事の目次"` | 本文の見出しから作る目次（押すとその見出しへ）。`levels=3` は見出しと小見出し、`levels=2` は見出しだけ。目次のある本文では、見出しに文書の順の `id`（`h-1`, `h-2` …）が付き、`/pages/about#h-2` のようにリンクでも飛べます（目次の無い本文の HTML は変わりません）。見出しが無ければ何も出ません。データベースは引きません |
| `::: stores tryon=1 layout=grid` | ショップで使う実店舗（店名・住所・電話・今日の営業・曜日ごとの営業時間・近い臨時休業 / 臨時営業）。`tryon=1` はお店で試着を受ける店舗だけ。店舗の情報は実店舗の設定が正なので、ここを直すとどのページの店舗の段も変わります |
| `::: include page=footer-note` | **部品のページ**（下の「部品のページ」）の本文をここに差し込む（0122） |
| `::: current part=title` | **ひな形**（下の「ひな形の割り当て」）の中で、今の記事・商品の部品を出す。記事: title（タイトル）/ image（アイキャッチ）/ content（本文）/ excerpt（抜粋）/ author（書いた人）/ tags（タグ）/ prev-next（同じブログの前後の記事）。商品: title（ブランドと商品名）/ image（画像）/ price（いちばん安い SKU の値段、会員価格を含む）/ buy（SKU を選んで買うフォーム）/ content（説明）/ tags / attributes（項目の表）/ breadcrumb（パンくず）/ size-chart（採寸表）/ reviews（レビュー）。商品一覧: title（カテゴリーの名前か「すべての商品」）/ image（カテゴリーの画像、0113）/ content（カテゴリーの説明、0113）/ products（商品の並びとページ送り）/ filters（タグで絞る。カテゴリーで絞ったまま）/ subcategories（子カテゴリー。すべての一覧なら上の段のカテゴリー）/ breadcrumb（パンくず）。法務のページ: title（ページの名前）/ legal（文面。ショップの設定のまま）。ブログの一覧（0114）: title（ブログの名前。タグで絞ったら「#タグ の記事」）/ content（ブログの説明）/ articles（記事の並びとページ送り）/ filters（タグで絞る）/ breadcrumb（パンくず）。合わない部品は何も出さない。ひな形でないふつうのページ（お店のトップのひな形を含む）では、title・image・excerpt がそのページ自身のタイトル・アイキャッチ・SEO の説明になる |

- 見たままの編集のブロックの一覧（「お店」「デザイン」）から入れられ、右の設定の欄で選びます。
- 商品・ページ・記事は、お店の画面と同じ読み取りの道で引きます。会員限定のもの・見えないものは、合わない人には出ません。価格は見る人の単価（会員なら会員価格）です。
- **今すぐ買う**は、カートに入れてそのまま配送先の画面へ進みます。最終確認の画面（特商法の表示）は省きません。会員限定で買えない商品には、ボタンの代わりに案内が出ます。
- 検索・カテゴリー・カード・商品は 1 ページに 8 つまでです（多い分は空）。
- アイコンは Lucide（ISC License、© Lucide Contributors / Cole Bemis）の一部を `src/pages/icons.ts` に収めたもので、SVG を自由に貼ることはできません（生の HTML と同じ穴になるため）。

### 部品のページ（0122）

同じ文面（お知らせの帯・送料の案内・店舗の案内など）を、いくつものページ・記事・ひな形に置きたいときは、それを 1 つのページに書いて「部品」にします（メンテナの決定 2026-11-06）。

- ページの編集の画面で **「部品として使う」** にすると、そのページは `/pages/<handle>`・メニュー・サイトマップ・ヘッドレスの API の一覧と 1 つに出ません（メニューの欄はいつも「出さない」になります）。部品は公開しておきます（下書き・予約公開の前・ゴミ箱・会員限定のページは差し込みません）。
- 使う側の本文に `::: include page=<部品の URL の名前>` を書きます（見たままの編集では「部品を差し込む」）。お店の画面・ヘッドレスの API・プレビューで、描く前にその行を部品の本文に置き換えます。部品を直すと、差し込んだどのページも変わります。
- 部品のページでなくても、公開中のふつうのページを差し込めます（ページの URL でも見せたいとき）。
- 差し込みは 1 段だけです（部品の中の `::: include` は外す）。1 つの本文に 3 つまで（多い分は外す）。見つからない部品の行は何も出ません。
- 差し込んだ後の本文が 1 つの本文として扱われます。見せる相手の囲み（下）を部品の中に置けば見る人で出し分け、ブロックの数の上限（商品を並べる 2 つなど）は合わせた本文に効きます。
- AI 用 API（`POST /api/v1/pages`・MCP の `page_save`）では `is_part` で読み書きします。データベースの更新 `0122_page_parts` が当たるまで「部品として使う」の欄は出ません（`::: include` はふつうのページを差し込むのに使えます）。

### 見せる相手の囲み（同梱モジュール「会員の条件」）

`::: audience id=<条件の id> title="…"`〜`:::` で囲んだ中身は、条件に合う人にだけ出ます（合わない人には HTML にも残りません）。書き方は docs/audiences.md「本文のブロック」。

## 3. 安全のための作り

- 「ビジュアル」の編集はブラウザの中だけで、保存するときに上の書式に直して送ります（`src/content/editor-client.ts`）。書式で表せない飾り（文字の色・大きさなど）は文字だけが残ります。貼り付けは文字だけです（ほかのサイトの見た目やスクリプトを持ち込まない）。JS の無いブラウザでは「Markdown」の入力欄だけになります。

- 本文を HTML にするのは**お店の画面を描くとき**です（`src/pages/markdown.ts`）。DB には書いた文字だけを置き、HTML は置きません。だから「ページ」の項目を持つ人でも、ショップのドメインに任意の HTML やスクリプトを入れられません（テーマの JS を入れられるのは「デザイン（テーマ）」の項目だけです。docs/themes.md）。
- 変換は文字を 1 回なめるだけで、長い入力でも遅くなりません。変換した HTML は Worker のメモリにページの版ごとに覚え、同じページを描くたびには変換しません。
- 下書きのページはお客様から見えません（DB の RLS）。モジュールが OFF のショップでは、公開中のページも出しません。

## 4. お店の画面の使い方との関係

お店の画面の使い方（docs/storefront.md）が「カートと購入だけ」「使わない」のショップでは、ページを出さず外のサイトへ回します（商品の一覧と同じ扱い。ページは外のサイトが持つため）。

外のサイトで Banto のページを出すときは、ヘッドレスの公開 API（`GET /api/shops/:shop/pages`・`/pages/:handle`）から本文の書式と描いた HTML を読めます（docs/headless.md「ページ・ブログ」）。お店の画面の使い方に関係なく読めます。

## ひな形の割り当て（0101）

作ったページを、お店の画面の「ひな形」にできます（メンテナの決定 2026-11-03）。ページの一覧の「ひな形の割り当て」から選びます（項目 `content`、書くのは DB の `page_layouts_set` だけ。値は `shops.settings.page_layouts`）。

- **お店のトップ**（`/`）: 商品の一覧のかわりに、そのページの本文を出します。すべての商品は `/products`、カテゴリーの一覧は `/categories/<カテゴリー>` で、トップとは別の URL です（docs/storefront.md「URL」）。`<title>` はページの SEO のタイトル、無ければショップの名前。canonical はお店のトップ。
- **ブログの記事**（ブログごと）: ひな形の本文の `::: current part=content` に記事の本文を差し込み、ひとつの本文として描きます。見せる相手の囲み・ブロックの数の上限・日時のブロック（記事の日時）はひな形と記事の両方に効きます。テーマの記事の見出し・日付・アイキャッチ・タグは出さず、並びはひな形が決めます。SEO（タイトル・説明・canonical・OG の画像）は記事のもの。
  - 本文の部品は**囲み（グループ・カラムなど）の外**に置きます。囲みの中に置くと、記事の本文はそのまま入りますが、記事の中のお店のブロック（商品・カードなど）は出ません。
- 割り当てたページが見えない（非公開・予約公開の前・ゴミ箱・会員限定）ときは、黙って今までの画面に戻します（ページは匿名の読み取りで引く）。
- **Liquid のテーマ**: ひな形は `templates/page`（ひな形のページに `template_suffix` があれば `templates/page.<suffix>`）の中に描きます。ヘッダーとフッターはテーマのまま。テンプレートが `page.title` を出すなら、ひな形には見出しを出さないテンプレート（例: `templates/page.bare.liquid`）を選んでください。記事のひな形の `page.title` は記事のタイトルです。
- **商品詳細**（0102）: ショップ全体のひな形と、カテゴリーごとの上書き。商品の主カテゴリーから親へたどって、最初に割り当てのあるカテゴリーのもの、無ければショップ全体のものを使います。部品は既定のテーマの商品ページと同じもので、**買うフォーム（`part=buy`）を必ず置いてください**（値段・在庫・会員価格・会員限定は DB の判定のまま。ひな形から変えられません）。SEO・canonical・商品の構造化データは今までどおり Banto が出します。会員限定の商品にゲストが来たときの「会員の方だけ」の画面はひな形を使いません。Liquid のテーマでも、テーマの `templates/product` は使いません。部品はテーマに `snippets/part-<部品>.liquid` があればテーマの見た目、無ければ既定のテーマの見た目です（docs/themes.md「ひな形の部品」）。
- **ひな形のプレビュー**: ひな形に割り当てたページを編集の画面でプレビューすると、見本の記事（そのブログのいちばん新しい記事）か商品（割り当てたカテゴリー、無ければショップ全体の最初の商品）、ブログの一覧なら割り当てたブログの一覧の 1 ページ目で描きます。保存していない下書きのひな形がそのまま使われます。
- **商品一覧**（0103）: すべての一覧とカテゴリーの一覧に共通のひな形と、カテゴリーごとの上書き（そのカテゴリーから親へたどって近いもの）。すべての一覧は `/products` と、トップのひな形が無いときのトップ、カテゴリーの一覧は `/categories/<カテゴリー>`。**商品の並び（`part=products`）を必ず置いてください**。並べ方・ページ送り・会員限定の商品の出し分けは今の一覧と同じです。タグで絞った一覧（`?tag=`）もひな形で描き、検索の結果（`?q=`）は今までの画面です（ひな形の中のタグのリンクは今のカテゴリーのまま）。Liquid のテーマでも、テーマの `templates/collection` は使いません。部品はテーマに `snippets/part-<部品>.liquid` があればテーマの見た目、無ければ既定のテーマの見た目です（docs/themes.md「ひな形の部品」）。
- **法務の 3 つのページ**（0104）: 特商法の表記・プライバシーポリシー・返品についてに共通のひな形と、ページごとの上書き。文面は今までどおりショップの設定の必須項目で、ひな形の中の**文面の部品（`part=legal`）**が出します。その部品が見る人に見える本文に無ければ（置いていない・見せる相手の囲みの中）、ひな形を使わず今までの画面で出します（文面の無い法務のページを作らせないため）。連携サイトのページに向ける設定（0062）が生きていれば、そちらが先です。
- **ブログの一覧**（0114）: ブログごとに、一覧（`/blogs/<ブログ>`）のひな形を割り当てられます。**記事の並び（`part=articles`）を必ず置いてください**（見る人に見える本文に無ければ今までの一覧）。並べ方（公開した日時の新しい順・12 本ずつ・深さ 1,200 本まで）は今の一覧と同じで、**タグで絞った一覧（`?tag=`）と 2 ページ目以降（`?page=`）もひな形で描きます**（タグで絞った一覧は今までどおり検索エンジンに載せない）。RSS のリンクは今までどおり。Liquid のテーマでは `templates/blog` は使わず `templates/page` の中に描き、部品は `snippets/part-<部品>.liquid` で描けます（`part-articles` には `blog`・`articles`・`current_tags`・`paginate`。docs/themes.md「ひな形の部品」）。データベースの更新 `0114_page_layouts_blogs` が当たるまで、割り当ての欄は出ません。
- カート・レジは割り当てられません（特商法の最終確認に直結するため）。
