# LINE（公式アカウントでの通知）

Banto は LINE の **Messaging API** で 2 種類の通知を送れます（どちらも同梱プラグイン、既定 OFF）。

| プラグイン | 送る相手 | 送る内容 |
| --- | --- | --- |
| LINE 通知 | 運営者（設定した利用者 ID） | 新しい注文・キャンセル・在庫僅少（購入者の個人情報は送らない） |
| LINE で購入者に知らせる | **LINE でログインした会員** | 注文の受付（注文番号・合計）・発送 |

外部プラグイン（MA など）からの宣伝のメッセージは、Banto が同じ公式アカウントで送ります（§4、0105）。

## 1. チャネルアクセストークン（ショップごと）

1. LINE Developers で、ショップの LINE 公式アカウントの **Messaging API チャネル** を開きます（無ければ LINE Official Account Manager で公式アカウントを作り、Messaging API を有効にします）。
2. 「Messaging API 設定」の **チャネルアクセストークン（長期）** を発行します。
3. 管理画面 → ショップ → プラグイン →「LINE 公式アカウント」に貼って保存します。
   - サイトの秘密（`SESSION_SECRET`）から作った鍵で **暗号化して** 保存し、画面には二度と出しません（CLAUDE.md §1-5 の例外、メンテナの決定 2026-10-17）。`SESSION_SECRET` を変えたら入れ直してください。
   - 入れなければ、変数とシークレットの `LINE_CHANNEL_ACCESS_TOKEN` を使います（ショップが 1 つだけの運営なら、こちらでも構いません）。

データベースの更新 `0021_line_messaging` が要ります。

## 2. 購入者に知らせる

1. **LINE でログイン** のモジュールを設定します（docs/members.md 3-3）。
2. LINE ログインのチャネルと Messaging API のチャネルを **同じプロバイダー** に置きます。プロバイダーが違うと、会員の LINE の利用者 ID が合わず届きません。
3. LINE でログインのモジュールの画面で **「友だち追加を促す」** を選びます。公式アカウントを友だちに追加していない人には届かないためです。
   - 「同意の画面に、友だち追加のチェックを出す」（`bot_prompt=normal`）か「同意の後に、友だち追加の画面を開く」（`bot_prompt=aggressive`）。
4. プラグインの画面で「LINE で購入者に知らせる」を有効にします。

- 知らせるのは、LINE と結びついた会員の注文だけです（ゲスト・メールだけの会員には送りません。メールの通知は「メール通知」プラグイン）。
- 文に載せるのは注文番号・合計・ショップ名だけです（住所・氏名は載せません）。
- 友だちでない・ブロックされた人に送れなかったときは、失敗にしません（再送しても届かないため）。

## 3. 取引の知らせと宣伝の分け方（メンテナの決定 2026-11-03）

- 取引の知らせ（注文の受付・発送・運営者への知らせ）は、Banto の同梱プラグインが送ります（§2）。
- 宣伝（だれに・いつ・何を送るか）は外部プラグイン（MA など）が決め、送るのは Banto の **LINE で送る口**（§4）です。
  トークンは Banto の 1 か所だけに置き、プラグインには LINE の利用者 ID もトークンも渡しません。
- メールと同じ線です（注文のメールは同梱プラグイン、宣伝のメールは外部プラグインの送り手）。

## 4. LINE で送る口（外部プラグイン向け、0105）

外部プラグインは、AI 用トークンのスコープ `line:send`（項目 `marketing`）で、会員 1 人に 1 通を頼めます。Banto は頼まれた 1 通を送って結果を返すだけで、
列・予約の時刻・再送・セグメント・頻度の制御は持ちません（プラグインの仕事です）。

```http
POST /api/v1/customers/{会員 ID}/line-message
Authorization: Bearer banto_...
Idempotency-Key: rule42-member-20261103        ← 必須。8〜64 字の英数字・- ・_。同じ文を送り直すときは同じキー
Content-Type: application/json

{ "text": "秋の新作が入りました",
  "image_url": "https://cdn.example.com/aki.jpg",
  "buttons": { "text": "見てみる", "actions": [{ "label": "新作を見る", "url": "https://shop.example.jp/collections/new" }] } }
```

- 受けるのは `text`（2,000 字まで）・`image_url`（https）・`buttons`（`text` 160 字まで、`actions` 1〜4 個、`label` 20 字まで、`url` は https）だけです。Banto が LINE の形に組み直します（Flex Message などをそのまま受けません）。
- 応答は `{ "id": "…", "status": "…" }`。LINE の利用者 ID は返しません。
  | status | 意味 |
  | --- | --- |
  | `sent` | 送りました |
  | `no_line` | LINE でログインしていない会員（メールなどへ回すかはプラグインが決める） |
  | `not_friend` | 公式アカウントを友だちに追加していない・ブロックされた |
  | `quota` | 宣伝の月の上限に届いた（`limit` と `count` も返す） |
- LINE の側の一時的な失敗は 502 です。**同じ `Idempotency-Key` で送り直してください**。Banto は記録の行の id を LINE の再送キー（`X-Line-Retry-Key`）にするので、重ねて届きません。決まったキー（sent など）で呼ぶと、送らずに同じ結果を返します。
- **宣伝の月の上限**（日本時間の月ごと、ショップの設定 `line_marketing_limit`、既定 150、0 なら送らない）: 管理画面 → プラグイン →「LINE 公式アカウント」（画面の上のリンク、または「LINE 通知」「LINE で購入者に知らせる」のカードのリンク）で変えます。公式アカウントの料金プランの無料の通数を宣伝で使い切って、注文の知らせが届かなくならないためです。取引の知らせは数えません。今月の数は `GET /api/v1/line/usage`。
- 記録（`line_messages`）に残すのは会員 ID・状態・時刻だけです（文も LINE の利用者 ID も残しません。400 日で消えます。退会した会員の ID は外します）。
- 送れるのは LINE でログインした会員だけで、§2 の 2・3（同じプロバイダー・友だち追加）も同じです。
- 宣伝の中身（景品表示法など）と、公式アカウントの規約は運営者の責任です。
