# 配送日時の指定

購入者が配送先の画面で **お届け希望日** と **時間帯** を選べる同梱モジュールです（既定 OFF）。

## 1. 使い方

1. 管理画面 → アップデートで、データベースの更新 `0018_delivery` を適用します。
2. ショップ設定 → モジュール →「配送日時の指定」を ON にします。
3. モジュールの「開く」で、選べる範囲（注文日から **最短 N 日後〜最長 M 日後**。既定は 3〜14 日）と、選べる時間帯を決めます。

- 時間帯はヤマト運輸・佐川急便で共通の区分です: 午前中 / 14〜16時 / 16〜18時 / 18〜20時 / 19〜21時。どちらも「指定なし」を選べます。
- 日付はデプロイの時間帯（`BANTO_TIMEZONE`、既定 Asia/Tokyo）の「今日」から数えます。
- 選んだ内容は、最終確認画面・管理画面の注文の画面・送り状 CSV に出ます。
- 注文の確定の直前にもう一度確かめます（確認画面を開いたまま日付が変わり、選んだ日が範囲から外れたら選び直してもらいます）。

## 2. ヘッドレス

選べる日と時間帯は、カート API（`GET` / `POST /api/shops/<slug>/cart`）の応答の `delivery`（`{ dates: [{ value, label }], slots: [{ value, label }] }`。モジュールが OFF なら `null`）で受け取れます。連携側はカートの画面・配送先の画面で、追加の呼び出しなしに選択欄を出せます。
チェックアウト API の配送先に `delivery_date`（`YYYY-MM-DD`、`dates[].value`）と `delivery_slot`（`am` / `14-16` / `16-18` / `18-20` / `19-21`、`slots[].value`）を足せます。モジュールが OFF なら無視します。選べない値は `invalid_address`（`invalid` に `delivery_date` / `delivery_slot`）。確認の内容は `confirmation.delivery_request`。

## 3. 仕組み（開発者向け）

- 判定は `src/modules/delivery-time/`（`checkDelivery`）、チェックアウト（`src/commerce/checkout.ts`）が配送先と一緒に検証して quote に署名する。選択肢は同じモジュールの `deliveryOptions`（同梱テーマの配送先の画面とヘッドレスのカートの応答で 1 本。キャッシュ済みのショップ行だけで決まり、DB を読まない）。
- 注文には `orders.delivery`（jsonb、0018 の汎用の器）。チェックアウトが予約の customer に載せ、注文を入れるときにトリガーで写す（確定の関数は触らない）。
