# クーポン CSV（取り込みと書き出しの形）

同梱モジュール「クーポン」の **CSV から取り込む**（`/admin/shops/<id>/modules/coupons/import`、0043_coupon_import）で使う形です。
ほかのカートから移したクーポンを、人が表計算ソフトで直しても、AI に直してもらっても、同じ形で取り込めます。
WooCommerce の取り込みで「要確認」になったクーポンも、この形で書き出されます（docs/woo-import.md）。

## 取り込みの流れ

1. CSV を選ぶ（または貼り付ける）→ **確かめる**。何も作らずに、行ごとに「作れる / 既にある / 直す必要がある（理由）」を出します。
2. 結果を見て **取り込む**。直す必要がある行は作りません。CSV を直して、もう一度確かめてください。
3. 既にあるクーポン（同じ `code`、または同じ `ref`）は作りません。何度流しても重複しません。

1 回 500 行・2MB まで。文字コードは UTF-8（書き出しは BOM 付き）。

## 列

1 行目に列の名前を書きます。並びは自由で、使わない列は省いてかまいません（`kind` と、`name` か `code` は必須）。

| 列 | 中身 |
| --- | --- |
| `code` | クーポンのコード（英大文字・数字・`_` と `-`、32 文字まで。小文字は大文字にします）。空なら、コードを持たないクーポン（あとで発行して配るもの） |
| `name` | 名前（100 文字まで）。空ならコード |
| `kind` | 必須。`percent`（割合）/ `fixed`（定額）/ `free_shipping`（送料無料） |
| `value` | 割合は 1〜100、定額は円。送料無料は空 |
| `starts_at` / `ends_at` | `2026-10-01`、`2026-10-01 10:00`、`2026/10/01 10:00`（ショップの時間帯）、または時差つきの ISO 8601。日付だけの `ends_at` はその日の 23:59 |
| `usage_limit` | 全体で使える回数（1〜100000）。空なら上限なし |
| `per_customer_limit` | 1 人が使える回数（1〜1000） |
| `combinable` | ほかのクーポンと併用できるか（`true` / `false`。既定 `false`） |
| `audience` | `public`（誰でも）/ `members`（ログイン中の会員だけ）。既定 `public` |
| `member_emails` | **この会員だけが使える** クーポンにするとき、会員のメールアドレス（`;` かスペースで区切る、1 行 5,000 人まで）。共通のコードは作らず、会員ごとに 1 枚発行します（会員ページの「マイクーポン」に出ます）。`code` は重複の確認にだけ使います（`ref` が無ければ `csv:<code>` を ref にします）。**全員がこのショップの会員でなければ、その行は作りません** |
| `min_subtotal_jpy` / `max_subtotal_jpy` | 対象商品の合計の下限・上限（円） |
| `min_qty` | 対象商品の点数の下限（999 まで） |
| `exclude_sale` | セール品を除く（`true` / `false`） |
| `product_slugs` / `exclude_product_slugs` | 対象・除く商品のスラッグ（`;` かスペースで区切る）。ひとつでも Banto に無ければ、その行は作りません |
| `category_slugs` / `exclude_category_slugs` | 対象・除くカテゴリーのスラッグ（子孫のカテゴリーと、追加カテゴリーで入っている商品を含む） |
| `tags` / `exclude_tags` | 対象・除くタグ（`;` で区切る。どれか 1 つを持つ商品） |
| `brands` / `exclude_brands` | 対象・除くブランド（`;` で区切る。商品のブランドと、前後の空白・大文字小文字を区別せずに比べる。0044） |
| `payment_methods` | 使える支払い方法（`;` かスペースで区切る）: `stripe` / `komoju`（KOMOJU のすべて）/ `komoju:credit_card`・`komoju:paypay` など。空ならどれでも（docs/coupons.md「支払い方法の条件」。0044） |
| `active` | 有効にするか（`true` / `false`。既定 `true`） |
| `ref` | 取り込み元での ID（例: `woocommerce:123`、100 文字まで）。同じ `ref` のクーポンが既にあれば作りません |
| `note` | メモ。取り込みでは読みません |
| `source_meta` | 取り込み元の設定（JSON）。取り込みでは読みません。人や AI が直すときの材料 |

`true` / `false` は `1` / `0`、`yes` / `no`、`はい` / `いいえ` でも書けます。数は `1,000` のような桁区切りも読みます。

### 作らない行（止める側に倒す）

- **ここに無い列に値がある行**（例: `allowed_roles`）。書いたつもりの制限を黙って捨てると、値引きが広がるためです。
- 値の形・範囲が違う行（理由は画面に出ます。検査は AI 用 API と同じ `banto_api_coupon_apply`）。
- Banto に無い商品・カテゴリーのスラッグがある行。
- `member_emails` に、このショップの会員でないメールアドレスがある行。

## WooCommerce の「要確認」の CSV を直す

WooCommerce の取り込みは、本体の項目だけを写します。プラグインの設定があるクーポンはこの形で書き出され、

- 本体の項目（割引・期限・回数・最低金額・対象の商品とカテゴリー・メールアドレスの制限）は列に入っています。
- プラグインの設定は `source_meta` に JSON のまま入っています（例: `{"_acfw_allowed_customers":[12,34]}`）。鍵の意味はプラグインごとに違うので、Banto は解釈しません。
- `active` はすべて `false`、`note` に「WooCommerce では有効」「プラグインの設定: 鍵の名前」などが入っています。

直し方の例（会員 ID で使える人を絞ったクーポン）:

1. 取り込みの画面で「顧客 ID とメールアドレスの対応表を作る」を押して保存する（`wc_customer_id,email`）。
2. `source_meta` の顧客 ID を表でメールアドレスに直し、`member_emails` に `;` 区切りで入れる。
3. ほかに Banto で表せない設定が無ければ、`active` を `true` にする。
4. 「CSV から取り込む」で確かめてから取り込む。

Banto の列で表せない設定（ロールでの制限、BOGO、無料の商品の追加、自動適用、AND と OR を組み合わせたカートの条件など）があるクーポンは、`active` を `false` のまま取り込み、管理画面で考え直すか、作り直してください。

## AI に直してもらうとき

対応表と要確認の CSV を AI に渡し、取り込みの画面にある文（下と同じ）で頼みます。できた CSV は **必ず「確かめる」で結果を見てから** 取り込んでください。会員でない人・無い商品・知らない列は Banto が止めます。

```text
添付の 1 つ目の CSV は Banto のクーポン CSV です。source_meta の列に、元のカート（WooCommerce とそのプラグイン）でのクーポンの設定が JSON で入っています。2 つ目の CSV は、WooCommerce の顧客 ID とメールアドレスの対応表です。

次の決まりで、1 つ目の CSV を Banto で取り込める形に直してください。
1. 列の名前と並びは変えない。note と source_meta は残してよい（取り込みでは読まれない）。
2. source_meta の設定が「この顧客だけが使える」（顧客 ID・ユーザー ID の一覧）なら、対応表でメールアドレスに直し、member_emails に ; 区切りで入れる。対応表に無い ID があれば、その行の note に書き、active を false にする。
3. 開始日・終了日・回数・最低金額など、Banto の列で表せる設定は、その列に入れる。日付は 2026-10-01 や 2026-10-01 10:00 の形。
4. Banto の列で表せない設定（ユーザーの権限グループでの制限、BOGO、無料の商品の追加、自動適用、AND と OR を組み合わせた条件など）が 1 つでもある行は、active を false にし、note に何が表せなかったかを書く。条件を緩めたり、推測で別の条件に置き換えたりしない。
5. 意味のわからない設定がある行も、active を false にして note に書く。
6. すべての設定を Banto の列で表せた行のうち、note に「WooCommerce では有効」とある行は active を true にする（書き出しの時点では、そのまま取り込んでも制限が外れないよう、すべて false になっている）。
7. 最後に、行ごとに何を変えたかの一覧を出す。
```

AI 用トークン（docs/ai-access.md）を持つ AI なら、CSV を通さずに `coupon_create` と `coupon_grants_issue`（会員 id で発行）、`customers_list`（メールアドレスで会員を探す）で同じことができます。その場合も、表せない設定のあるクーポンは無効で作るよう頼んでください。
