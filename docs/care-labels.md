# 洗濯表示（同梱モジュール）

商品ページに洗濯表示（取扱い表示）を出す同梱モジュールです（既定 OFF。データベースの更新 `0127_mod_care_labels` が要ります）。
アパレルなど、洗濯表示のある商品を売るショップ向けです。

## 1. 使い方

1. ショップ設定 → モジュール →「洗濯表示」を ON にします。
2. **記号の絵を上げる**: モジュールの画面（「洗濯表示」）の「記号の絵」で、記号ごとにファイルを選んで保存します。
   - 洗濯表示の記号は、国によっては GINETEX の登録商標で、記号そのものの形が守られています。そのため **Banto には記号の絵を入れていません**。
   - 日本規格協会などから入手した公式のデータ（PNG・WebP・JPEG・SVG）を使ってください。使ってよいかは、入手したときの条件で確かめてください。
   - ブラウザで長い辺 256px までの PNG に縮めてから送ります。置き場は画像の置き場の `care/<ショップ>/` です。
   - 絵を上げていない記号は、お客様の画面では意味の文（例:「液温40℃まで、洗濯機で弱い洗濯ができる」）で出ます。
3. **カテゴリーで決める**: カテゴリーの画面の「洗濯表示」から、区分ごとに記号を選びます。付記（「ネット使用」「裏返し」など）は 1 行に 1 つ、8 つまで・40 文字までです。
4. **違う商品だけ商品で決める**: 商品の画面の「洗濯表示」から。商品で決めていなければ、主カテゴリーから親へたどって近いカテゴリーのものを使います（写さずに、表示するときに決めます）。何も選ばず付記も空にして保存すると、その段では決めない状態に戻ります。

## 2. 記号

JIS L 0001:2024（2024 年 8 月 20 日の改正、ISO 3758:2023 に合わせたもの）の記号番号で持ちます。区分（記号番号の 1 桁目）ごとに 1 つまで選べます。

| 区分 | 記号番号 |
| --- | --- |
| 洗濯（1） | 190・170・160・161・150・151・140・141・142・130・131・132・110・111・100 |
| 漂白（2） | 220・210・200 |
| タンブル乾燥（3） | 320・310・300 |
| 自然乾燥（4） | 440・445・430・435・420・425・410・415 |
| アイロン（5） | 530・520・510・511・500 |
| ドライクリーニング（6） | 620・621・610・611・600 |
| ウエットクリーニング（7） | 710・711・712・700 |

- 2024 年の改正で足された記号は、液温 30℃までの手洗い（111）と、底面温度 120℃までスチームなしのアイロン（511）です。アイロンの温度は 210 / 160 / 120℃ になりました。
- 意味の文は Banto が書いた短い説明です（規格の本文ではありません）。正確な定義は JIS L 0001:2024 を見てください。

## 3. お客様の画面

- 既定のテーマ: 商品ページの採寸表の下に「洗濯表示」を出します。記号ごとに絵（あれば）と意味の文、その下に付記です。
- 商品詳細のひな形（固定ページ）: 部品 `::: current part=care`。
- Liquid のテーマ: `product.care`（無ければ `null`）。

```liquid
{% if product.care %}
  <ul>
    {% for s in product.care.symbols %}
      <li>{% if s.image %}<img src="{{ s.image.url }}" alt="" width="40">{% endif %}{{ s.label }}</li>
    {% endfor %}
  </ul>
  {% for n in product.care.notes %}<p>{{ n }}</p>{% endfor %}
{% endif %}
```

  `symbols` の各要素は `code`（記号番号）・`group`（区分、1〜7）・`label`（意味の文）・`image`（`url`・`width`・`height`、上げていなければ `null`）です。
- ヘッドレス: `GET /api/shops/<ショップ>/products/<商品>` の `product.care`（同じ形。モジュールが OFF・無ければ `null`）。

## 4. AI 用 API

- `PUT /api/v1/products/{ref}/care`・`PUT /api/v1/categories/{ref}/care`（スコープ `products:write`。`ref` は ID か URL の名前）。本文は `{ "symbols": ["141", "210", "300", "445", "511"], "notes": ["ネット使用"] }`。`{}` で外します（商品ならカテゴリーのものを使う）。
- MCP は `care_set`（`target` は `product` か `category`）。
- 記号の絵は API では変えません（管理画面だけ）。
- 社内の商品マスタ・生産管理のシステムに記号番号があれば、そのまま写せます。

## 5. 仕組み（開発者向け）

- データ: `products.care`・`categories.care`（`{ symbols, notes }` か `null`。形は DB の制約 `banto_care_ok`）、`shops.care_symbols`（記号番号 → 置き場の画像。`banto_care_symbols_ok`、書くのは `care_symbols_set`（項目 catalog）だけ）。
- お客様の画面へは、商品とカテゴリーは今までの読み取りに列が増えるだけ、絵の表は公開のショップ行（`banto_shop_public_json` の `care_symbols`、モジュールが ON のときだけ）。DB の往復は増えません。
- どの段のものを使うかは `src/care-labels/care.ts` の `resolveCare`（材料はキャッシュ済みのカテゴリー）。表示の部品は `src/care-labels/html.tsx`、管理画面は `src/modules/care-labels/admin.tsx`。
- 組成（綿 100% など）は、商品のカスタム項目で持ってください（このモジュールには入れていません）。
