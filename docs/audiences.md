# 会員の条件（同梱モジュール audiences）

会員の独自項目（ランク・ポイント・地域など）を組み合わせた条件に**名前を付けて登録**し、ページのブロック・会員限定の商品・会員価格で「だれに見せるか・だれが買えるか・いくらにするか」を決めるのに使います。
WooCommerce の「ロール」や「会員ランクのメタ」で分けていたことを、Banto では会員の独自項目と、この条件で書きます。

- 既定は OFF です。管理画面 → ショップ → モジュール →「会員の条件」を ON にします（データベースの変更 `0097_audiences` が要ります）。
- 会員機能（ショップの設定の「会員」）と、会員の独自項目（ショップの設定の「会員の独自項目」）を先に用意してください。
- 扱えるのは権限の項目「マーケティング（marketing）」を持つ人です。

> この文書は段階ごとに書き足していきます。今使えるのは「条件の登録」と「本文のブロック」までです。会員限定の商品・会員価格・会員限定のページは、順に加わります。

## 条件の書き方

管理画面の組み立てでは、次を選べます。

- **ログインしている会員であること**
- 独自項目の条件を並べて「すべて満たす（かつ）」か「どれかを満たす（または）」
  - **どれかに合う**（`gold, platinum`。大文字小文字・前後の空白は区別しません）
  - **どれにも合わない**
  - **以上 / 以下**（数の項目。ポイント・購入回数など）
  - **値が入っている**

それより複雑な入れ子は「JSON で書く」の欄に書きます。

```json
{ "all": [
    { "member": true },
    { "any": [ { "attr": "rank", "in": ["gold", "platinum"] }, { "attr": "points", "gte": 10000 } ] },
    { "not": { "attr": "region", "in": ["overseas"] } }
] }
```

| 形 | 意味 |
| --- | --- |
| `{ "member": true }` | ログイン中の会員 |
| `{ "attr": "鍵", "in": [...] }` | 独自項目がどれかの値（文字で比べる） |
| `{ "attr": "鍵", "gte": 数 }` / `{ "attr": "鍵", "lte": 数 }` | 数の大小（数として読めない値は合わない） |
| `{ "attr": "鍵", "set": true }` | 値が入っている（空の文字は入っていない） |
| `all` / `any` / `not` | かつ / または / ではない |

- 深さ 4 段・条件 20 個まで。鍵は会員の独自項目の定義にあるものだけです。
- **ゲスト（ログインしていない人）は独自項目を持ちません。** 独自項目の条件はゲストには合いません。`not` だけの条件（「海外でない」）はゲストにも合うので、会員だけにしたいときは「会員であること」と組み合わせてください。
- クーポンの条件の「会員の独自項目」（`conditions.attributes`）も、同じ規則で判定します。

## URL のパラメータの条件（表示の出し分けだけ）

広告やメールのリンクに付けたコード（`?ref=insta`）や、URL の値（`?tag=sale`）でも判定できます。

```json
{ "any": [
    { "param": "ref", "in": ["insta", "line"], "remember": true },
    { "param": "tag", "in": ["sale"] }
] }
```

- 管理画面の組み立てでは、「独自項目」の欄で **URL のパラメータ** を選び、パラメータの名前（英数字と `_`、40 字まで。大文字小文字は区別しません）を入れます。比べ方は独自項目と同じです（数の比べ方は最初の値で比べます）。
- **ゲストにも効きます。** 会員だけにしないときは「ログインしている会員であること」を外します。会員の条件と組み合わせることもできます（ゴールド会員 かつ `ref=insta`）。
- **訪問のあいだ覚える**（`remember`）を付けると、その値で来た人がほかのページへ移っても合い続けます。値はお店の画面の Cookie に入り、最後にお店の画面を開いてから 30 分で消えます。同じパラメータで別の値の URL を開くと、その値に置き換わります。付けなければ、その URL の画面だけです（検索の条件などは覚えないほうが自然です）。
- **URL はだれでも付けられます。** URL のパラメータを含む条件は、本文のブロックの出し分けだけに使えます（会員限定の商品・会員価格では選べません。データベースが断ります）。隠したい情報や、値引きそのものには使わないでください（値引きはクーポンで）。
- ヘッドレスでは、連携サイトが見る人の URL の値を `p.<名前>` で渡します（`GET /api/shops/{shop}/pages/about?p.ref=insta`）。覚える値も、連携サイトが覚えて同じ形で渡してください。

## 本文のブロック（ページ・記事）

ページ（同梱モジュール「ページ」）と記事（「ブログ」）の本文に、見せる相手の囲みを書けます。

```text
誰にでも見える文

::: audience id=<条件の id> title="ゴールド会員"
ゴールド会員の方だけに見える文。中に見出し・画像・レイアウトの囲み・商品を並べるブロックも書けます。
:::
```

- 書式の欄で書くときは、始まりの行に管理画面の「会員の条件」の一覧の「本文に貼る行」をそのまま写します。`title` は編集の画面の目印だけで、お客様には出ません。
- **合わない人には、中身が HTML にも残りません**（ブラウザで隠すのではなく、Banto が描く前に本文から取り除きます）。ゲストに見せたいときは `{ "not": { "member": true } }` の条件を作ります。
- 条件が消えた・id が違う・モジュールが OFF のときは、だれにも見せません。囲みは入れ子にでき、レイアウトの囲みの中にも外にも書けます。
- 記事の一覧の抜粋・RSS には、囲みの中身を使いません（だれが見るか決まらないため）。抜粋を自分で書いた記事は、その抜粋が出ます。
- 見たままの編集では、ブロックの一覧の「デザイン」の**見せる相手**で入れられます（書式を書かなくてよい）。右の設定で会員の条件を選び、枠の中に中身を書きます。囲みは点線の枠と「見せる相手: …」の目印で出て、保存すると同じ書式に戻ります。条件を 1 つも作っていないショップでは、一覧に出ません。
- 条件を直すと、お店の画面に効くまで最大 1 分ほどかかります（条件の一覧を短く覚えているため）。会員のランクを変えたときは、会員の Cookie が入れ直されるまで最大数分です。
- ヘッドレスの公開 API（`GET /api/shops/{shop}/pages/{handle}`・`…/articles/{article}`）は、`Authorization: Bearer <会員トークン>` を付けるとその会員に合わせた `body` と `html` を返します（付けなければゲスト。壊れたトークンは 401 `invalid_member_token`）。囲みのある本文の応答には `Vary: Authorization` が付きます。連携サイトでキャッシュするときは、会員ごとに分けるか、囲みのあるページをキャッシュしないでください。
- Liquid のテーマでは `customer` に `logged_in`（true）・`attributes`（条件で使っている独自項目の値だけ）・`audiences`（合う条件の名前の並び。URL のパラメータの条件は数えません）が入ります（`{% if customer.audiences contains "ゴールド会員" %}`）。ゲストの `customer` は空です。テーマで出し分けた部分はブラウザに届く HTML の出し分けなので、秘密の文には本文の囲みを使ってください（どちらも HTML に残らない点は同じですが、テーマはショップ全体に効くため）。

> 本文の囲みは読み物の出し分けです。値段の割引や「買えるかどうか」は、注文のときにデータベースが判定する会員価格・会員限定の商品で決めます。

## 判定の仕組みと、会員の Cookie に入る値

- 判定の正はデータベース（`banto_audience_ok`）です。画面を描くときは同じ規則の写し（`src/members/audience.ts`）を使い、同じ答え合わせの表のテストで両方を縛っています。
- **条件で使っている独自項目の値**は、会員本人の Cookie（ヘッドレスでは会員トークンの access）に入ります。数分ごと（ヘッドレスは refresh のたび）に入れ直すので、ランクを変えてから画面に出るまで最大数分かかります。画面のたびに会員の情報を取りに行かないための仕組みです。
- 会員本人の Cookie・トークンには、条件で使っている鍵の値だけが入ります（社内メモのような、条件で使っていない項目は入りません）。本人が自分の値を見ることはできるので、本人に見せたくない値を条件に使わないでください。
- 買えるか・価格は、注文のときにデータベースが最新の値で判定します（会員限定の商品・会員価格が加わったとき）。

## ランクの付け方

- 管理画面の「会員」で 1 人ずつ、CSV で一括、AI 用 API（`customers:write`）で入れられます。CRM を使っているなら、CRM のランクを Banto に写す形です（docs/ai-access.md §7）。
- 購入額で自動でランクを上げる仕組みは Banto の本体には入れません。注文の hooks を受けて計算し、API で書き込む外部プラグインで行ってください。
