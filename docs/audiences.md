# 会員の条件（同梱モジュール audiences）

会員の独自項目（ランク・ポイント・地域など）を組み合わせた条件に**名前を付けて登録**し、ページのブロック・会員限定の商品・会員価格で「だれに見せるか・だれが買えるか・いくらにするか」を決めるのに使います。
WooCommerce の「ロール」や「会員ランクのメタ」で分けていたことを、Banto では会員の独自項目と、この条件で書きます。

- 既定は OFF です。管理画面 → ショップ → モジュール →「会員の条件」を ON にします（データベースの変更 `0097_audiences` が要ります）。
- 会員機能（ショップの設定の「会員」）と、会員の独自項目（ショップの設定の「会員の独自項目」）を先に用意してください。
- 扱えるのは権限の項目「マーケティング（marketing）」を持つ人です。


## 条件の書き方

管理画面の組み立てでは、次を選べます。

- **ログインしている会員であること**
- 独自項目の条件を並べて「すべて満たす（かつ）」か「どれかを満たす（または）」
  - **どれかに合う**（`gold, platinum`。大文字小文字・前後の空白は区別しません）
  - **どれにも合わない**
  - **以上 / 以下**（数の項目。ポイント・購入回数など）
  - **値が入っている**

それより複雑な入れ子は「JSON で書く」の欄に書きます。

```json
{ "all": [
    { "member": true },
    { "any": [ { "attr": "rank", "in": ["gold", "platinum"] }, { "attr": "points", "gte": 10000 } ] },
    { "not": { "attr": "region", "in": ["overseas"] } }
] }
```

| 形 | 意味 |
| --- | --- |
| `{ "member": true }` | ログイン中の会員 |
| `{ "attr": "鍵", "in": [...] }` | 独自項目がどれかの値（文字で比べる） |
| `{ "attr": "鍵", "gte": 数 }` / `{ "attr": "鍵", "lte": 数 }` | 数の大小（数として読めない値は合わない） |
| `{ "attr": "鍵", "set": true }` | 値が入っている（空の文字は入っていない） |
| `all` / `any` / `not` | かつ / または / ではない |

- 深さ 4 段・条件 20 個まで。鍵は会員の独自項目の定義にあるものだけです。
- **ゲスト（ログインしていない人）は独自項目を持ちません。** 独自項目の条件はゲストには合いません。`not` だけの条件（「海外でない」）はゲストにも合うので、会員だけにしたいときは「会員であること」と組み合わせてください。
- クーポンの条件の「会員の独自項目」（`conditions.attributes`）も、同じ規則で判定します。

## URL のパラメータの条件（表示の出し分けだけ）

広告やメールのリンクに付けたコード（`?ref=insta`）や、URL の値（`?tag=sale`）でも判定できます。

```json
{ "any": [
    { "param": "ref", "in": ["insta", "line"], "remember": true },
    { "param": "tag", "in": ["sale"] }
] }
```

- 管理画面の組み立てでは、「独自項目」の欄で **URL のパラメータ** を選び、パラメータの名前（英数字と `_`、40 字まで。大文字小文字は区別しません）を入れます。比べ方は独自項目と同じです（数の比べ方は最初の値で比べます）。
- **ゲストにも効きます。** 会員だけにしないときは「ログインしている会員であること」を外します。会員の条件と組み合わせることもできます（ゴールド会員 かつ `ref=insta`）。
- **訪問のあいだ覚える**（`remember`）を付けると、その値で来た人がほかのページへ移っても合い続けます。値はお店の画面の Cookie に入り、最後にお店の画面を開いてから 30 分で消えます。同じパラメータで別の値の URL を開くと、その値に置き換わります。付けなければ、その URL の画面だけです（検索の条件などは覚えないほうが自然です）。
- **URL はだれでも付けられます。** URL のパラメータを含む条件は、本文のブロックの出し分けだけに使えます（会員限定の商品・会員価格では選べません。データベースが断ります）。隠したい情報や、値引きそのものには使わないでください（値引きはクーポンで）。
- ヘッドレスでは、連携サイトが見る人の URL の値を `p.<名前>` で渡します（`GET /api/shops/{shop}/pages/about?p.ref=insta`）。覚える値も、連携サイトが覚えて同じ形で渡してください。

## 本文のブロック（ページ・記事）

ページ（同梱モジュール「ページ」）と記事（「ブログ」）の本文に、見せる相手の囲みを書けます。

```text
誰にでも見える文

::: audience id=<条件の id> title="ゴールド会員"
ゴールド会員の方だけに見える文。中に見出し・画像・レイアウトの囲み・商品を並べるブロックも書けます。
:::
```

- 書式の欄で書くときは、始まりの行に管理画面の「会員の条件」の一覧の「本文に貼る行」をそのまま写します。`title` は編集の画面の目印だけで、お客様には出ません。
- **合わない人には、中身が HTML にも残りません**（ブラウザで隠すのではなく、Banto が描く前に本文から取り除きます）。ゲストに見せたいときは `{ "not": { "member": true } }` の条件を作ります。
- 条件が消えた・id が違う・モジュールが OFF のときは、だれにも見せません。囲みは入れ子にでき、レイアウトの囲みの中にも外にも書けます。
- 記事の一覧の抜粋・RSS には、囲みの中身を使いません（だれが見るか決まらないため）。抜粋を自分で書いた記事は、その抜粋が出ます。
- 見たままの編集では、ブロックの一覧の「デザイン」の**見せる相手**で入れられます（書式を書かなくてよい）。右の設定で会員の条件を選び、枠の中に中身を書きます。囲みは点線の枠と「見せる相手: …」の目印で出て、保存すると同じ書式に戻ります。条件を 1 つも作っていないショップでは、一覧に出ません。
- 条件を直すと、お店の画面に効くまで最大 1 分ほどかかります（条件の一覧を短く覚えているため）。会員のランクを変えたときは、会員の Cookie が入れ直されるまで最大数分です。
- ヘッドレスの公開 API（`GET /api/shops/{shop}/pages/{handle}`・`…/articles/{article}`）は、`Authorization: Bearer <会員トークン>` を付けるとその会員に合わせた `body` と `html` を返します（付けなければゲスト。壊れたトークンは 401 `invalid_member_token`）。囲みのある本文の応答には `Vary: Authorization` が付きます。連携サイトでキャッシュするときは、会員ごとに分けるか、囲みのあるページをキャッシュしないでください。
- Liquid のテーマでは `customer` に `logged_in`（true）・`attributes`（条件で使っている独自項目の値だけ）・`audiences`（合う条件の名前の並び。URL のパラメータの条件は数えません）が入ります（`{% if customer.audiences contains "ゴールド会員" %}`）。ゲストの `customer` は空です。テーマで出し分けた部分はブラウザに届く HTML の出し分けなので、秘密の文には本文の囲みを使ってください（どちらも HTML に残らない点は同じですが、テーマはショップ全体に効くため）。

> 本文の囲みは読み物の出し分けです。値段の割引や「買えるかどうか」は、注文のときにデータベースが判定する会員価格・会員限定の商品で決めます。

## 会員限定の商品

商品の編集の画面の「会員限定」で、会員の条件と扱いを選びます（データベースの変更 `0098_audience_products` が要ります）。

| 扱い | 条件に合う会員 | 合わない会員 | ログインしていない人 |
| --- | --- | --- | --- |
| **見せる相手を絞る**（既定） | 一覧・検索・詳細に出て、買える | 出ない（URL で来ても 404） | 一覧・検索に出ない。URL で来ると「会員の方だけ購入できます」とログインへのリンク（商品の名前・価格・画像は出しません） |
| └ **存在も隠す** | 同じ | 同じ | URL で来ても 404 |
| **だれにでも見せるが、買えるのは合う会員だけ** | 買える | 商品は見えるが「対象の会員の方だけ購入できます」 | 商品は見えるが「会員の方だけ購入できます」とログインへのリンク |

- **買えるかはデータベースが判定します。** カートに入れるとき・カートの値付け・注文の確定の前（購入手続きの一本道）に、会員の **最新の** 独自項目で判定し直します（Cookie の値ではありません）。ランクを下げた会員のカートからは、次に開いたときに外れます。ログインしていない人は会員限定の商品を買えません。
- 一覧・検索・サイトマップ・タグとカテゴリーの件数・貼れるタグ・ヘッドレスの匿名の読み取りからは、見せる相手を絞った商品が消えます（データベースの行の権限で絞るので、読み取りの道を問わず消えます）。**商品フィード**（Google・Meta）には、どちらの扱いの会員限定の商品も出しません（フィードはだれでも買える商品の一覧のため）。
- 会員には、ログインしているあいだ、合う条件の商品を足した一覧・詳細を出します（会員の画面はキャッシュしません）。
- **URL のパラメータを使う条件は選べません**（だれでも付けられるため）。商品に使っている条件に、あとから URL のパラメータの条件を足すこともできません。商品に使っている条件は消せません。
- ヘッドレス: 商品の一覧・詳細に `Authorization: Bearer <会員トークン>` を付けると、その会員に合わせて返します（モジュールが ON のショップだけ。壊れたトークンは 401 `invalid_member_token`）。詳細には `members_only`（会員限定の商品か）と `purchasable`（この見る人が買えるか）が入ります。ゲストが見せる相手を絞った商品を開くと 403 `members_only`（存在も隠す商品は 404）。カートに買えない商品を入れると 403 `members_only`。
- Liquid のテーマでは `product.members_only` と `product.purchasable` が使えます（買えないときは `product.available` も false）。
- AI 用トークンの API（`/api/v1` と MCP）からも、商品の `audience`（条件の id か名前）・`audience_mode`・`audience_hide` を読み書きできます（データベースの変更 `0144_api_product_audience`、docs/ai-access.md §18）。

## 会員価格

「会員の条件」の画面の **会員価格** で、条件に合う会員の単価を決めます（データベースの変更 `0099_member_prices` が要ります）。

- **対象**: 商品（URL の名前）・SKU（品番）を指定するか、カテゴリー（子のカテゴリーの商品も）・タグ・ブランドのどれかに当てはまる商品。もっと細かい条件（「タグが sale かつ 商品の独自項目 season が ss」など）は JSON の欄に書きます。

  ```json
  { "all": [ { "tag": ["sale"] }, { "attr": "season", "in": ["ss"] }, { "not": { "brand": ["ノーブランド"] } } ] }
  ```

- **価格**: 固定の価格（円、税込）か、通常の価格から何 % 引き（1〜99、円未満は切り捨て）。期間（始まり・終わり）と、有効 / 止めるを選べます。
- **いくつか当てはまるときは、いちばん安い価格**になります。通常の価格より高い決まりは効きません。
- **単価はデータベースが決めます。** カートの値付け・最終確認・決済の額・注文の明細のどれも、会員の **最新の** 独自項目で決めた同じ単価です。最終確認を見たあとで決まりやランクが変わったときは、注文を確定せずに確認画面を出し直します。
- **クーポンは会員価格にかかります**（会員価格から、さらに値引き）。
- **表示**:
  - 合う会員には、その会員の単価を「会員価格 ¥2,400（通常 ¥3,000）」と出します。
  - ログインしていない人には、通常の価格と並べて「¥3,000（会員価格 ¥2,400）」と出します。これは当てはまる決まりのうちいちばん安いもので、どの条件の価格かは出しません。
  - 合わない会員には、通常の価格だけを出します。
- 会員の条件に URL のパラメータの条件は使えません。モジュールを OFF にすると、会員価格は効かなくなります。
- ヘッドレス: 商品の詳細の SKU に `price_jpy`（この見る人の単価。会員トークンの会員なら会員価格）・`regular_price_jpy`（通常の価格）・`member_price_jpy`（ゲストに見せる会員価格、無ければ null）。決済の確定で価格が変わっていたら 409 `price_changed`。Liquid は `variant.member_price`・`variant.regular_price`。
- 商品の一覧（カード）の価格は、今は通常の価格のままです。

## 会員の条件ごとの送料無料

「設定」→「配送と税」の **会員の条件ごとの送料無料**（データベースの変更 `0171_audience_free_shipping` が要ります）で、条件に合うログイン中の会員だけ、別の金額で送料無料にします。

- 例: 「ゴールド会員は 0 円以上（いつでも送料無料）」「シルバー会員は 3,000 円以上で送料無料」。それ以外の人は、ショップ全体の「この金額以上で送料無料」のままです。
- **0 円** を入れると、その条件の会員はいつでも送料無料です。いくつか当てはまるときは、**いちばん低い金額** を使います（ショップ全体の金額のほうが低ければそちら）。判定に使うのは、ショップ全体の金額と同じく **値引き前の商品の合計** です。全国一律でも都道府県別でも効きます。
- 決まりは 10 件まで。会員の条件に URL のパラメータの条件（表示用）は選べません。ゲストには効きません。モジュールを OFF にすると効かなくなります。消した会員の条件の決まりは効かず、次に保存したときに外れます。
- **当てはまるかはデータベースが決めます**: 最終確認の画面を出すときと、注文を確定する前に、会員の **最新の** 独自項目で判定します（会員の Cookie・会員トークンに入っている数分前の値は使いません）。確認のあとでランクが変わって送料が変わるときは、注文を確定せずに確認画面を出し直します。
- 最終確認の画面では、送料の行に「会員特典で送料無料」と出ます。
- 判定には会員のログインのセッションも確かめます（ログアウト・端末の取り消しの後の古い Cookie・会員トークンでは効きません）。データベースに聞けなかったときは、送料がかかる側で計算します。
- **カートの「あと ○円で送料無料」** は、ログイン中の会員なら会員の条件の金額も見て出します（例: ゴールド会員には「会員特典で送料無料です」、シルバー会員には「あと ¥1,200 で送料無料」）。判定には、会員の Cookie・会員トークンに入っている独自項目（数分ごとに入れ直す）と、覚えておいた会員の条件の一覧（60 秒）を使います。カートの画面のためにデータベースへ問い合わせを増やしません（覚えた一覧が切れたときだけ 1 回引きます）。そのため、ランクが変わった直後の数分はカートの目安がずれることがあります。**送料の額を決めるのは最終確認の画面** です（そこでは会員の最新の独自項目で判定します）。
  - 既定のテーマのカートにこの目安の 1 行が出ます。Liquid のテーマは `cart.banto_free_shipping`（`over`・`remaining`・`applied`・`member`・`coupon`。送料無料の金額が無い・カートに買える商品が無ければ null。送料無料のクーポンが入っていれば `coupon: true`・`applied: true`・`remaining` は 0）で描けます。配送先の画面は `checkout.banto_free_shipping`（同じ形）と `checkout.free_shipping_applied` が同じ目安で、`checkout.free_shipping_over` はショップ全体の金額です。既定のテーマのカートは、送料無料のクーポンが入っているときは目安の行を出しません（クーポンの案内の文が出ます）。
  - ヘッドレスのカートは `shipping.viewer_free_over_jpy`（見る人の送料無料の金額）・`shipping.member_free_applies`（会員特典の金額か）・`shipping.remaining_for_free_jpy`（その金額まであといくら）を返します。`free_over_jpy` はショップ全体の金額のままです。
- お客様の画面の公開の設定（`shop_public_get`）には、名前を付けた決まりの **名前と金額だけ** を出します。会員の条件の id・名前の無い決まりの金額は出しません。決まりがあることだけを `member_free: true` で知らせます。
- **送料の案内のページ**（`/<ショップ>/shipping`）には、決まりに **お店の画面に出す名前** を入れたものだけを「ゴールド会員の方は送料無料」「シルバー会員の方は 3,000 円以上のご注文で送料無料」のように出します。会員の条件の名前はお客様には見せないので、名前を空にした決まりは案内に出ません。
- ヘッドレス: カートの `shipping.member_free`（`[{ label, free_over_jpy }]`、名前を付けた決まりだけ）と、quote の `confirmation.shipping_free_reason`（`audience` = 会員の条件の送料無料、`threshold` = ショップ全体の金額、`null` = 送料がかかる）。Liquid は配送先の画面の `checkout.member_free_shipping`、最終確認の `checkout.confirmation.shipping_free_reason`。

### 送料無料とセール商品（0183）

ショップ全体の「この金額以上で送料無料」と、会員の条件ごとの送料無料の決まりのそれぞれに、**セール商品を金額に含まない** の印を付けられます（「設定」→「配送と税」。データベースの変更 `0183_free_shipping_exclude_sale` が要ります。既定は含む）。

- **セール商品** は、SKU に通常価格（`compare_at_price_jpy`）を入れて、それより安く売っている商品です。会員価格・クーポンの値引きはセールに数えません。
- 印を付けた決まりは、値引き前の商品の合計から **セール商品の分を引いた金額** で比べます。印の無い決まりは今までどおり商品の合計で比べます。当てはまる決まりが 1 つでも満たされれば送料無料です。
- 使い方の例:
  - **セール商品だけのご注文は送料無料にしない**（会員の条件 A の方）: 会員の条件 A・**1 円以上**・セール商品を含まない。セール商品だけのカートは 0 円と比べるので送料がかかり、セール以外の商品が 1 点でもあれば送料無料です。
  - **セール商品を除いて 11,000 円以上で送料無料**（すべての人）: ショップ全体の金額 11,000 円・セール商品を含まない。
- カートの「あと ○円で送料無料」も、印のある決まりはセール商品を除いた金額で数えます。送料の案内のページには「セール商品を除いて ¥11,000 以上のご注文で送料無料」「ゴールド会員の方は送料無料（セール商品だけのご注文を除く）」のように出ます。
- Liquid: `cart.banto_free_shipping.excludes_sale`（ショップ全体の印）、配送先の画面の `checkout.free_shipping_excludes_sale` と `checkout.member_free_shipping[].excludes_sale`。ヘッドレス: カートの `shipping.free_over_excludes_sale` と `shipping.member_free[].exclude_sale`、`shipping.remaining_for_free_jpy` は印を数えた残り。
- 当てる前は欄が出ず、今までどおり商品の合計で比べます。

## 会員限定のページ・記事

ページ・記事の編集の画面の右の「会員限定」で、会員の条件を選びます（データベースの変更 `0100_audience_content` が要ります）。

- 条件に合う会員だけが開けます。一覧・メニュー・サイトマップ・RSS・「記事を並べる」のブロックには、ログインしていない人と合わない会員には出ません（データベースの行の権限で絞ります）。合う会員には、ブログの記事の一覧にも出ます。メニュー（ヘッダー・フッター）には、会員限定のページは出しません。
- ログインしていない人が URL で来ると「会員の方だけ」とログインへのリンク（題・本文は出しません）。**存在も隠す** に印を付けると 404 です。ログインしていて合わない会員も 404 です。
- URL のパラメータを使う条件は選べません。ページの一部だけを出し分けるときは、本文の「見せる相手」のブロックを使います。
- ヘッドレス: `Authorization: Bearer <会員トークン>` を付けると、その会員に合わせて返します。ゲストが会員限定のページ・記事を開くと 403 `members_only`（存在も隠すものは 404）。

## 判定の仕組みと、会員の Cookie に入る値

- 判定の正はデータベース（`banto_audience_ok`）です。画面を描くときは同じ規則の写し（`src/members/audience.ts`）を使い、同じ答え合わせの表のテストで両方を縛っています。
- **条件で使っている独自項目の値**は、会員本人の Cookie（ヘッドレスでは会員トークンの access）に入ります。数分ごと（ヘッドレスは refresh のたび）に入れ直すので、ランクを変えてから画面に出るまで最大数分かかります。画面のたびに会員の情報を取りに行かないための仕組みです。
- 会員本人の Cookie・トークンには、条件で使っている鍵の値だけが入ります（社内メモのような、条件で使っていない項目は入りません）。本人が自分の値を見ることはできるので、本人に見せたくない値を条件に使わないでください。
- 買えるか・価格は、注文のときにデータベースが最新の値で判定します（会員限定の商品・会員価格が加わったとき）。

## ランクの付け方

- 管理画面の「会員」で 1 人ずつ、CSV で一括、AI 用 API（`customers:write`）で入れられます。CRM を使っているなら、CRM のランクを Banto に写す形です（docs/ai-access.md §7）。
- 購入額で自動でランクを上げる仕組みは Banto の本体には入れません。注文の hooks を受けて計算し、API で書き込む外部プラグインで行ってください。
