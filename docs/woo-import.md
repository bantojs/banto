# WooCommerce から取り込む（同梱モジュール）

WooCommerce の商品データを Banto に移す手順です。モジュールは既定で OFF なので、使うときだけ ON にします。

## 1. 準備

1. Banto の管理画面 → アップデートで、データベースの更新（`0008_catalog`・`0009_catalog_import`）を適用しておきます。
2. ショップ設定 → **モジュール** → 「WooCommerce から取り込み」を **ON** にします。

取り込み方は 2 つあります。**REST API がおすすめ**です（カスタム項目が正確に移り、税込 / 税抜の設定と旧 URL も分かります）。REST API が使えないサイト（http のサイト、外部からの API 呼び出しを止めているサイト）は CSV で取り込みます。どちらで取り込んでも同じ商品は同じものとして更新されるので、混ぜても重複しません。

## 2-A. REST API から読む（おすすめ）

1. WordPress の管理画面 → **WooCommerce** → **設定** → **高度な設定** → **REST API** → **キーを追加**。
   - 説明: 「Banto への移行」など
   - 権限: **読み込み**
   - 「API キーを生成」を押し、表示された **コンシューマーキー**（`ck_…`）と **コンシューマーシークレット**（`cs_…`）を控えます（シークレットはこの画面でしか見られません）。
2. Banto の「WooCommerce から取り込み」→「REST API から取り込む」に、ショップの URL（`https://` から）とキー・シークレットを入れて「読み込む」。
3. 確認画面が出たら、「3. 取り込む」へ進みます。

- キーは **このブラウザから WooCommerce に直接** 送るだけで、Banto のサーバーには送らず、保存もしません。移行が終わったら WooCommerce でキーを削除してください。
- 商品 1,000 件なら、バリエーションの読み込みを含めて数分かかります（WooCommerce の速さによります）。
- 税込 / 税抜は WooCommerce の設定から自動で判定し、確認画面のチェックに反映します（変えることもできます）。
- 「接続できませんでした」と出るときは、セキュリティ系のプラグインやサーバーの設定が、外部のサイトからの REST API の呼び出しを止めている可能性があります。CSV で取り込んでください。
- パーマリンク設定が「基本」のサイトでも使えます。

## 2-B. CSV を書き出す

**列名が英語の CSV が必要です。** WooCommerce は列名を管理画面の言語に訳して書き出します（日本語のサイトなら「タイプ」「名前」…）。訳はバージョンによって変わるので、Banto は英語の列名だけを読みます。日本語の列名の CSV を選ぶと、取り込まずにこの手順を案内します。

1. WordPress の管理画面 → **ユーザー** → **プロフィール** → **言語** を **English (United States)** にして保存します（自分の画面だけが英語になります。サイトの表示や他のユーザーには影響しません）。
2. **Products** → **Export**（商品 → エクスポート）で書き出します。商品名・カテゴリー名などの中身は日本語のままです。
3. 書き出したら、言語は元に戻して構いません。

書き出しの設定:

- 書き出す列: すべて
- 書き出す商品タイプ: すべて（シンプル・バリエーション商品・バリエーション）
- 書き出す商品カテゴリー: **絞らない**（カテゴリーで絞ると、カテゴリーを持たないバリエーション＝SKU が書き出されません。少しだけ試したいときは、書き出した CSV から行を減らしてください）
- **カスタムメタを書き出す**（Export custom meta）: カスタム項目（素材・洗濯表示など）も移すならチェックを付けます

書き出したファイルは **Excel で開いて保存し直さずに** そのまま使ってください。Excel で保存すると文字コードが Shift_JIS になり（Banto は読めます）、長い数字（JAN）が `4.90123E+12` のように書き換わったり、日付の形が変わったりします。

### 価格を税抜で入力していた場合

Banto の価格はすべて **税込** です。WooCommerce → 設定 → 税金 →「税込価格で入力」が **「いいえ、税抜価格で入力します」** だったショップは、確認画面で「WooCommerce では価格を税抜で入力していた」にチェックを付けてください（CSV には、この設定が書き出されないため自動では分かりません）。

- 税区分（Tax class）ごとに税率を確かめます。既定は 標準 10%、`reduced-rate`（軽減税率）8%、`zero-rate` と課税しない商品（Tax status が none）は 0% です。
- 1 円未満の端数は 四捨五入（WooCommerce の表示と同じ）/ 切り捨て / 切り上げ から選びます。
- 販売価格・セール価格・通常価格のすべてを換算します。

### 税区分（軽減税率）

確認画面の税区分の行ごとに「Banto の区分」（標準税率 / 軽減税率 / 非課税）を選べます。既定は 標準 → 標準税率、`reduced-rate`（名前に「軽減」を含むものも）→ 軽減税率、`zero-rate` と課税しない商品 → 非課税です。税抜の換算をしないショップでも、区分は商品に入ります（docs/tax.md、0022_tracking の適用が必要。適用前は区分を入れずに取り込みます）。

Banto の区分は **商品ごと** です。SKU（バリエーション）ごとに区分が違う商品は、最初の SKU の区分にして確認事項に出します。

## 3. 取り込む

REST API で読み込むか CSV を選ぶと、確認画面が出ます。解析はブラウザの中で行われ、まだ何も書き込まれません。

確認画面で次を見ます。

- **取り込む内容**: 商品・SKU・カテゴリー・画像の数
- **確認事項**: 価格の無いバリエーション、在庫数の無い SKU、お取り寄せ可の SKU、無効なバリエーション、JAN の桁違い、メタ列のずれ、これからのセール・終わったセール、取り込まない種類の商品（グループ商品・外部リンク商品） など
- **取り込み方**: ブランドが複数ある商品の扱い、在庫の上書き、無効なバリエーション、バリエーションの画像、税抜価格の換算
- **カスタム項目**: 取り込む列にチェック。表示名とキーは変えられます。取り込んだ項目は**非公開**で作られます

「取り込む」を押すと、カテゴリー → 商品と SKU の順に書き込みます。終わったら、画像の取り込み方を選びます。

| 取り込み方 | 速さ | ページ |
| --- | --- | --- |
| **このページを開いたまま取り込む** | いちばん速い（4 商品ずつ同時に進める） | 終わるまで閉じない |
| **裏で取り込む**（0039） | Banto の定期処理（5 分おき）が少しずつ進める | 予約したらすぐ閉じてよい |

どちらも、途中で止まっても続きから取り込めます（取り込み済みの画像は飛ばします）。取り込めなかった画像は、理由ごとの枚数と一覧（CSV）で出ます。

### 裏で取り込む

予約するのは画像の公開の URL だけです（WooCommerce のキーは Banto に送りません）。進み具合は、取り込みの画面の上の「裏での画像の取り込み」に出ます（いつ開いても見られます）。

- 1 回（5 分おき）に進める枚数は **サイトの設定**（管理画面のダッシュボード →「サイトの設定」）の Cloudflare のプランで決まります。無料プランは 12 枚（1 時間に約 140 枚）、有料プラン（Workers Paid）や Node で動かしているときは 150 枚です。無料プランは 1 回の処理で使える通信の回数が少ないので、有料プランでないのに「有料プラン」にすると、途中で止まります。
- 一時的な失敗（つながらない・混み合っている・旧サイトの 5xx）は、間をあけて 3 回までやり直します。断られた（403）・無い（404）・画像でないものは、すぐ「取り込めなかった画像」になります。
- 「取り込めなかった画像をもう一度予約する」「残りの予約を取り消す」ができます。モジュールを OFF にすると止まり、ON に戻すと続きから進みます。
- 5MB を超える画像は、Banto のサーバーでは縮小しないので「5MB より大きい画像」として止まります。進み具合の欄の **「大きすぎる画像を縮小して取り込む」** を押すと、このページのブラウザで縮小して取り込みます（下の「大きすぎる画像」）。
- もっと速くしたいときは、`wrangler.jsonc` の Cron を `*/1 * * * *`（1 分おき）にすると約 5 倍になります（ほかの定期処理も 1 分おきになります）。

同じ CSV を何度取り込んでも重複しません。商品はスラッグ（SKU を小文字にしたもの）、SKU は品番で突き合わせて更新します。CSV に無い商品は消しません。

### 大きすぎる画像（5MB 超）

Banto のサーバーは画像を縮小しません（Workers の CPU の制限と、サーバーで画像処理をしない方針のため）。5MB を超える画像は、**管理画面のブラウザで縮小して**取り込みます（商品の画面から画像を追加するときと同じ、長辺 1600px の WebP と 400px のサムネイル）。

- **ページを開いたまま取り込んだとき**: 最後に自動で縮小して取り込みます。
- **裏で取り込んだとき**: 進み具合の欄の「大きすぎる画像を縮小して取り込む（○ 枚・このページで）」を押します。終わるまでページを閉じないでください。
- 旧サイトの画像はブラウザから直接読めないので（CORS）、元の画像は Banto が中継します（40MB まで。守りは URL からの取り込みと同じで、保存はしません）。
- 縮小した画像は元の URL と結びつけて登録するので、もう一度取り込んでも二重になりません。裏の取り込みの「取り込めなかった画像」からも外れます（0040）。
- 40MB を超える画像・ブラウザで開けない画像は一覧に残ります。手元で縮小して、商品の画面から追加してください。アニメーション GIF は 1 枚目だけの静止画になります。

## 対応表

| WooCommerce | Banto |
| --- | --- |
| 商品（simple / variable） | 商品。スラッグは SKU を小文字にしたもの（無ければ `wc-<ID>`） |
| バリエーション（variation） | SKU。属性（Attribute 1 name / value(s) …）は SKU の選択肢。カテゴリーの「SKU を分ける軸」は取り込んだ商品には写しません（属性の名前が軸と違うと取り込みが止まるため）。取り込んだ後に、カテゴリーの画面の「商品に当てる」か、商品の画面の「今の SKU から推す」で決めてください（0065） |
| Regular price / Sale price | セール中（期間内、または期間の指定なし）ならセール価格を販売価格、標準価格を通常価格（取り消し線で表示）。これからのセール・終わったセールは標準価格 |
| Tax status / Tax class | 税抜で入力していたときの換算にだけ使う（Banto の価格は税込） |
| Stock / In stock? | 在庫数。数量の無い SKU（在庫管理なし・お取り寄せ可）は 0 |
| GTIN, UPC, EAN, or ISBN | JAN / GTIN |
| Categories | 階層のまま（3 段まで）。いちばん深いものを主カテゴリーにし、他は追加カテゴリー（0042 より前の DB ではタグ） |
| Tags | タグ |
| Brands | ブランド（複数あれば 1 つを選び、残りはタグ） |
| Short description + Description | 説明（HTML はテキストにします） |
| Images・バリエーションの画像 | 商品の画像（URL から取り込み。ページを開いたままか、裏で。サムネイルは作りません）。バリエーションの画像は、そのバリエーションの属性（カラーなど）に結びます。サイズ違いで同じ画像を使っていれば、カラーだけに結びます（0063 より前の DB では商品全体の画像） |
| Meta: …・追加の列 | カスタム項目（選んだものだけ、非公開で） |
| Published（1 / 0 / -1） | 公開 / 非公開 / 非公開 |

取り込まないもの: グループ商品・外部リンク商品、配送クラス、重量と寸法、アップセル・クロスセル、レビュー、セールの予約（始まったら管理画面で価格を変えてください）、パーマリンク（旧 URL。REST API なら転送用の一覧を出せます）、会員のパスワードと注文の履歴（会員の名前・メールアドレス・住所は REST API から取り込めます。下の「会員の取り込み」）。

## カスタムメタの列ずれについて

WooCommerce の CSV 書き出しは、商品ごとにメタ項目の種類が違うと、50 行ごとの塊の中でメタ列の並びが変わることがあります。Banto は次のように扱います。

- ある列でよく出る値（yes / no など）が別の列に紛れ込んでいる塊は、その塊の商品のカスタム項目を取り込みません（確認事項に一覧が出ます）。
- 数値の列に文字が混ざっている項目は、既定でチェックを外し「値がそろっていません」と表示します。

数値どうしのずれ（寸法の列が入れ替わるなど）は見分けられません。寸法などを正確に移したい場合は、REST API から取り込んでください（メタを商品ごとに名前つきで受け取るので、ずれが起きません）。

## 旧サイトからの転送（REST API のときだけ）

REST API で取り込むと、商品と SKU を書き込んだあとに「旧 URL → 新 URL の一覧を保存（CSV）」が出ます。`old_url,new_url` の 2 列で、旧サイトの商品ページと Banto の商品ページ（`https://<Banto のドメイン>/<ショップ>/p/<スラッグ>`）の対応です。ドメインを Banto に切り替えるときに、DNS やサーバーの転送設定（301）に読み込んで、検索エンジンの評価やブックマークを引き継いでください。Banto 自身は転送の機能を持ちません。

## 会員の取り込み（REST API のときだけ）

WooCommerce の顧客（権限グループ「顧客」）の **名前・メールアドレス・住所** を、Banto の会員にします。パスワードは移しません（docs/members.md「WooCommerce（WordPress）の会員を移す」）。

1. 管理画面 → アップデートで `0012_member_auth` を適用します。
2. メール通知プラグインを有効にして送信元を入れ、ショップ設定で **「会員機能を有効にする」** をオンにします（オフのあいだは、取り込みの画面に設定へのリンクが出ます）。
3. 「REST API から取り込む」に URL とキーを入れ、「会員の取り込み」の **「会員を読み込む」** → 人数を確かめて **「○人を会員として取り込む」**。

- 住所は配送先（無ければ請求先）を、会員の「いつもの住所」にします。日本以外の住所は取り込みません。
- メールアドレスが無い顧客・同じアドレスの重複は飛ばします。
- 取り込んだ会員は、ログイン画面でメールアドレスを入れると届くコードかリンクで入れます。**Banto からは会員にお知らせを送らない** ので、運営者からお知らせしてください。
- 同じメールアドレスの会員が既にいれば、足りない項目だけ埋めます。何度やり直しても重複せず、会員が自分で入れた名前・住所は上書きしません。
- 100 人ずつ送ります。

## クーポンの取り込み（REST API のときだけ）

同梱モジュール「クーポン」を ON にしたショップで、「クーポンを読み込む」を押すと WooCommerce のクーポンを読み、Banto のクーポンにします（キーは商品と同じもの。読み込みだけの権限で足ります）。

| WooCommerce | Banto |
| --- | --- |
| 割引タイプ「パーセント割引」 | 割合（%） |
| 「定額のカート割引」 | 定額（円） |
| 「送料無料を許可」（割引額 0） | 送料無料 |
| 使用期限 | 終了日時 |
| クーポンあたりの使用制限 | 全体の上限（**残りの回数** で作る） |
| ユーザーあたりの使用制限 | 1 人あたりの上限。**誰が何回使ったか**（`used_by`）も移す（0023） |
| 使用制限 → 許可するメール | その人ごとの発行済みクーポン（会員はマイクーポン、会員でない人はコードの一覧）（0023） |
| 「個別使用のみ」 | 他のクーポンと併用できない |
| 商品・除外する商品・カテゴリー・除外するカテゴリー | 対象と条件（取り込み済みの商品・カテゴリーに写す） |
| 最小・最大の使用額、セール商品を除く | 対象商品の合計の下限・上限、セール品を除く |
| ブランド・除くブランド（WooCommerce 9.6 からの本体の機能） | 対象・除くブランド（名前に直して写す。除くブランドは、2 つ目以降のブランドを入れたタグでも除く。名前を読めなければ要確認）（0044） |

- **移さないもの**: 「商品ごとの定額割引」（Banto に無い）、期限切れ・上限に達したもの、Banto のコードに使えない文字を含むもの。理由は画面に出ます。
- **無効で作るもの**: 対象の商品・カテゴリーが Banto で 1 つでも見つからないクーポン（先に商品を取り込んでください）。値引きの対象が広がらないようにするためです。確かめてから「有効」にしてください。
- 同じコード・同じクーポン（WooCommerce の ID）が既にあれば作りません（何度流しても重複しません）。

### 1 人ごとの使用回数

「ユーザーあたりの使用制限」のあるクーポンは、WooCommerce に残っている「使った人」（会員の ID かメールアドレス）を読み、Banto の使用記録に入れます。WooCommerce で使い終えた人は、Banto でも使えません。

- 会員の ID はメールアドレスにそろえます（WooCommerce の顧客を読みます）。
- ゲストとして買っても会員として買っても数に入るよう、メールアドレスと、同じアドレスの Banto の会員の両方で数えます。**先に会員を取り込んでから** クーポンを取り込んでください。
- 取り込みを流し直すと、そのクーポンの取り込んだ使用を入れ直します（重なりません）。

### メールアドレスで使える人を絞ったクーポン

Banto には「このメールアドレスの人だけ使えるコード」の仕組みが無いので、**その人ごとのクーポン** にします（発行して配るクーポン、docs/coupons.md）。

- 元のコードは使えなくなり、コードは人ごとに変わります。
- Banto の会員がいれば、その会員に発行します（会員ページの「マイクーポン」に出ます）。
- 会員でない人には、使い捨てのコードを発行して画面からコードの一覧（CSV: クーポン・メールアドレス・コード）を保存できます。**Banto からは知らせない** ので、運営者から渡してください。
- 1 人あたりの上限まで使い終えた人には発行しません。`*@example.com` のようなワイルドカードは移しません（決められる人がいなければ無効で作ります）。

### プラグイン独自の設定があるクーポン（要確認）

Banto が写すのは **WooCommerce 本体の項目だけ** です（上の表）。Advanced Coupons などのプラグインが付けた設定（使える会員の指定・ロールでの制限・BOGO・カートの条件など）は、Banto では同じ動きになるか確かめられません。読み飛ばすと「会員限定」のつもりのクーポンが誰でも使えるようになるので、**気づいて止めます**。

- クーポンの `meta_data` に、WordPress 本体の値でも空・オフの値（`""` `no` `0` `false` `[]` など）でもないものがあれば「要確認」に分けます。どのプラグインかは問いません。
- 要確認のクーポンは **既定では作りません**（「無効のまま作る」も選べます。その場合も必ず無効で作ります）。
- 「要確認のクーポンを CSV に書き出す」で **Banto のクーポン CSV**（docs/coupon-csv.md）を保存します。本体の項目は列に入り、プラグインの設定は `source_meta` に JSON のまま入ります。`active` はすべて `false` で書くので、直さずにそのまま取り込んでも制限は外れません。
- 「顧客 ID とメールアドレスの対応表を作る」で、WooCommerce の顧客 ID とメールアドレスの表を保存します（このブラウザで作るだけで、Banto へは送りません）。会員 ID で使える人を絞ったクーポンは、この表でメールアドレスに直して `member_emails` に入れます。
- 直した CSV は、クーポンの「CSV から取り込む」で確かめてから取り込みます。AI に直してもらうときの頼み方はその画面と docs/coupon-csv.md にあります。**先に会員を取り込んでください**（`member_emails` の人が全員会員でなければ、その行は作りません）。

## 過去の注文の取り込み（REST API のときだけ）

「注文を読み込む」を押すと WooCommerce の注文を読み、注文番号のまま Banto に入れます（0023_woo_history の適用が必要）。**先に会員と商品を取り込んでください**（会員はメールアドレス、商品は SKU で結びます）。

| WooCommerce | Banto |
| --- | --- |
| 完了 | 発送済み（完了日を発送日に） |
| 処理中 | 支払い済み（未発送。送り状 CSV の対象になります） |
| キャンセル・払い戻し | キャンセル・返金済み |
| 保留・支払い待ち・失敗・下書き | 移さない |
| 明細・送料・値引き | 税抜と税額を足して税込に。明細の税率は税額から（8% / 10%） |
| 注文番号 | そのまま（接頭辞の付いた番号は WooCommerce の ID） |

- 会員のアカウントの購入履歴・注文照会・領収書・売上の集計に出ます。
- **在庫・クーポンの回数・メール通知・hooks・「購入後に配るクーポン」には触りません**（過去の記録として入れるだけ）。
- Banto に無い商品の明細は、品名とバリエーションだけで残します。
- 新しい注文の番号は、取り込んだ番号の続きからになります。Banto に同じ番号の注文が既にあれば、その注文は飛ばして画面に出します。
- 同じ注文（WooCommerce の ID）は二重に入れません。何度流しても大丈夫です。
- 日本円でない注文は移しません。
- 発送から一定期間（既定 180 日）を過ぎた注文の住所・連絡先は、次の定期処理で自動でマスキングされます（docs/backup.md・CLAUDE.md §8 と同じ扱い）。購入履歴（品名・金額）は残ります。

## パスワードの取り込み（任意）

WordPress の会員のパスワードを移すと、会員はこれまでと同じパスワードでログインできます。ショップ設定で **「パスワードでもログインできる」** をオンにしてから行います。

1. 管理画面 → アップデートで `0013_member_password` を適用します。
2. WordPress のデータベースから **`wp_users` 表を CSV で書き出します**（レンタルサーバーの phpMyAdmin →「エクスポート」→ 形式 CSV、「1 行目にカラム名を入れる」にチェック）。列 `user_email` と `user_pass` が要ります。
3. 「WooCommerce から取り込み」の **「パスワードの取り込み」** でファイルを選び、人数を確かめて取り込みます。

- ファイルはこのブラウザで読み、メールアドレスとパスワードのハッシュだけを Banto に送ります。
- 移すのは **WordPress 6.8 以降の形式（`$wp$2y$…`）と bcrypt（`$2y$…`）だけ** です。古い形式（`$P$…`、MD5 ベース）は移しません（その会員は初回はメールのコードで入ります）。
- 会員がいなければ作ります（名前・住所は「会員の取り込み」で入ります。どちらを先にしてもかまいません）。Banto でパスワードを決めた会員は上書きしません。
- **取り込んだら、書き出したファイルはパソコンから削除してください**（パスワードのハッシュが入っています）。
