# お知らせの文面

お客様に送る注文・お店で試着のメール・LINE の文面を、ショップごとに直せます（0154）。管理画面の「ショップの設定 → お知らせの文面」（項目 `settings`）。

- 何も直していない知らせは、既定の文面（今までと同じ）で送ります。
- お店で試着のお知らせ（お客様あての受付・ご用意・前日・延長・取り消し）は、モジュール「お店で試着」が ON のショップだけこの画面に出ます。
- 店舗あての知らせ・会員のログインのメール・お問い合わせのお知らせは直せません。
- LINE の文面は、「LINE 公式アカウント」の画面のテスト送信で実際の LINE に送って確かめられます（docs/line.md §2「テスト送信と最近の送信」）。

## 差し込み

文の中の `{{名前}}` に、注文の内容などが入ります。前後の空白は書いても構いません（`{{ number }}`）。

| 名前 | 中身 | 使える知らせ |
| --- | --- | --- |
| `shop_name` | ショップ名 | すべて |
| `customer_name` | お客様のお名前（無ければ「お客」） | メールだけ（LINE には氏名を載せない） |
| `number` | 注文番号・受付番号 | すべて |
| `total` | 合計（税込、¥3,300 の形） | 注文・お支払いのお願い |
| `order_details` | 注文番号・明細・値引き・合計・消費税・お届け先のかたまり | 注文のメール |
| `tracking` | お問い合わせ番号と配送状況のリンク | 発送のメール・発送の LINE（0179） |
| `return_policy` | 「返品について:」とショップの返品ポリシー | 注文のメール |
| `order_link` | ご注文の状況を確かめるリンク | 注文のメール・注文の LINE（0179） |
| `contact` | 「お問い合わせ:」とショップの連絡先 | 注文のメール・お店で試着のメール・お支払いのお願いのメール |
| `store_name` | 店舗名 | お店で試着 |
| `hold_until` | お取り置きの期限（メールは「11月27日（金）」、LINE は「11月27日」） | お店で試着のご用意・前日・延長 |
| `visit` | ご来店予定日の案内 | お店で試着の受付のメール |
| `items` | お申し込みの品目 | お店で試着のメール・お支払いのお願いのメール |
| `store_info` | 店舗の住所・電話・営業時間・臨時休業 | お店で試着のメール |
| `shop_link` | お店のリンク | お店で試着のメール |
| `pay_until` | お支払いの期限（「11月28日（金）15:00」、運営者の時間帯） | お支払いのお願い（0181） |
| `payment_link` | お支払いに進む・取りやめる画面のリンク（予約ごとの券つき、期限はお支払いの期限） | お支払いのお願い（0181） |

値が空の差し込みだけを書いた行は、行ごと消えます（お問い合わせ番号の無い発送・連絡先を入れていないショップなど）。文面の中で空行が続くところは 1 つの空行にまとめます（差し込んだ値の中の空行はそのまま）。

LINE の注文の知らせの既定の文面には、0179 から `order_link`（受付・発送）と `tracking`（発送）の行が入っています。LINE はリンクを自動でタップできるようにします。LINE の知らせは会員の注文だけなので、`order_link` はいつも会員の印（`&banto_member=1`）つきです。氏名・住所・メールアドレスは今までどおり LINE に載せません。

## LINE のカード（0179）

「お知らせの文面」の画面の上の「LINE の注文の知らせの見た目」で、注文の受付・発送の LINE を **文字だけ**（既定）か **カード**（Flex Message）から選べます（ショップの設定 `line_notice_style`、項目 `settings`）。

- カードは、見出し（ショップ名）・本文・ボタン（「配送状況」「ご注文の状況」）の決まった形です。形は Banto が 1 つだけ持ち、ショップが Flex の JSON を書く形は持ちません（載せる中身とリンクの先を Banto が確かめるため）。
- 本文は下の LINE の文面です。`{{order_link}}` は本文に出さずボタンに、`{{tracking}}` は本文にお問い合わせ番号だけを出し、配送状況はボタンにします。
- ボタンは https の URL だけです（公開の URL が http のときなどはボタンを出しません）。
- 通知の欄やカードを出せない端末には、文字だけのときと同じ文（リンク入り、400 文字まで）が出ます。
- お店で試着の知らせはいつも文字だけです。
- LINE がメッセージの形を断ったとき（400 で項目ごとの誤りが返る）は、友だちでないときと分けて配信を失敗にします（「LINE 公式アカウント」の最近の送信に出ます。LINE だけのお客様にはメールで届きます）。テスト送信でも分けて知らせます。
- 「LINE 公式アカウント」の画面のテスト送信も、選んだ見た目で送ります（見本の注文番号 1001 の、このショップの注文照会へのリンク）。

## お支払いのお願い（0181）

KOMOJU（コンビニ払い・銀行振込など）でお申し込みのあと、24 時間たってもお支払いが確認できないお客様に、1 回だけ「お支払いのお願い」を送れます。この画面の上の「お支払いのお願い（KOMOJU）」で **送る** にしたショップだけです（ショップの設定 `payment_reminder`、既定は送らない、項目 `settings`）。

- 送るのは「メール通知」（お客様あてだけ、運営者への控えは付けません）と「LINE で購入者に知らせる」（LINE と結びついた会員）です。「LINE だけ」を選んだ会員には LINE だけで送り、届かなければメールで送ります（docs/line.md §2）。
- 「メール通知」で「注文のメールを送らない（外部プラグインに任せる）」にしているショップは、メールを送りません（hooks の `checkout.payment_pending` は外部プラグインに届きます。外部プラグインは AI 用 API の `GET /api/v1/reservations/{id}/payment-reminder`（0182、docs/ai-access.md §26）で宛先・品目・お支払いに進むリンクを読んで送れます）。
- 文面のリンク（`payment_link`）の先は「お支払いに進む・取りやめる」の画面です（docs/plugins.md「KOMOJU のお支払いに戻る」）。リンクは予約ごとの券つきで、お支払いの期限まで使えます。秘密は載りません（開いてできるのはお支払いに進むか取りやめるかだけで、お金は動きません）。
- お支払いの期限まで 1 時間を切ったお申し込み・もう確定した・取りやめたお申し込みには送りません。送るのは Cron で、1 回の Cron で 50 件まで拾います。
- KOMOJU の「在庫を確保しておく時間」を 25 時間以下にしたショップには届きません（24 時間たった時点で、期限まで 1 時間を切っているため）。
- 送る時刻はお申し込みからおよそ 24 時間後で、お客様の時間帯（夜中など）は見ません。
- リンクの先の画面には、分析のタグ（GA4 など）を入れません（URL の券を渡さないため）。

## 決まり（保存できない文面）

知らせごとに **必ず入れる差し込み** があり、無ければ保存できません。明細・合計・お届け先・店舗の案内を消した知らせを送らないためです。

| 知らせ | メールの本文 | メールの件名 | LINE |
| --- | --- | --- | --- |
| 注文の受付 | `order_details` | `number` | `number` |
| 発送のお知らせ | `order_details`・`tracking` | `number` | `number` |
| お店で試着の受付 | `items`・`store_info` | `number` | `number` |
| ご用意・前日・延長 | `hold_until`・`items`・`store_info` | `number` | `number`・`hold_until` |
| お店で試着の取り消し | `number` | `number` | `number` |
| お支払いのお願い（0181） | `payment_link` | （無し） | `payment_link` |

ほかにも次のときは保存できません。

- その知らせで使えない名前（発送のお知らせ以外の `tracking`、LINE の `customer_name` など）
- `{{` と `}}` が組になっていない
- かたまり（`order_details`・`tracking`・`items`・`store_info`）を 2 回以上（LINE の `tracking` も）
- 件名が空・改行を含む・150 文字を超える
- 本文が空・長すぎる（メール 4,000 文字、LINE 2,000 文字）

決まりは DB（`banto_notice_spec`・`notice_text_set`）と画面（`src/notices/templates.ts`）の両方で確かめます。書けるのは `notice_text_set` だけです（AI 用 API の口はまだありません）。

## 送るとき

送る直前に、保存してある文面を今の版の決まりで確かめ直します。合わなければ（版が上がって必須の差し込みが増えたなど）、**その知らせだけ既定の文面で送ります**。送るのを止めると再送を重ねても届かないためです。既定で送っている文面は、管理画面に警告を出します。文面が読めないとき（DB の一時的な誤りなど）も既定の文面で送ります。

文面は `shop_notice_texts` に置きます（`shops.settings` には置きません。ショップ行はお店の画面のたびにキャッシュから読まれるため、長い文を載せないため）。読むのは送るとき（Cron の hooks の配信）だけです。

## 書き出し

バックアップの JSON には `shop_notice_texts` も入ります。復元では戻さないので、管理画面で入れ直してください。
