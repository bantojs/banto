# お店の行動を連携に渡す（同梱モジュール event_relay）

会員がお店の画面でした行動（商品を見た・記事を読んだ・カートに入れた、など）を、運営者が許した外部プラグイン（MA・自動化など）へ渡します。
「今回の訪問で決めた 3 商品を見た会員に LINE を送る」「スタッフ X のコーデ記事を 3 本読んだ会員にクーポンを配る」のような自動化を、プラグインが組めるようにするための口です。

- **Banto は行動を溜めません。** 届いた行動を、そのまま署名してプラグインへ送るだけです。溜めて条件を判定するのはプラグインです。
- 既定は OFF です。管理画面 → ショップ → モジュール →「お店の行動を連携に渡す」を ON にします（データベースの変更 `0107_mod_event_relay` が要ります）。
- 何を渡すかは、**連携ごとに運営者が許します**（下の「許し方」）。プラグインが求めていない行動は渡せません。
- 今の版で渡すのは、**ログインした会員の行動だけ**です（ゲストの行動はこれからの版で）。

> 会員の閲覧の行動を外部のサービスへ渡すことになります。**ショップのプライバシーポリシーに、どんな行動を・どこへ渡すかを書いてください。** 法律（個人情報保護法・電気通信事業法の外部送信の規律）の扱いは、運営者が専門家に確かめてください。

## 渡す行動

| 種類 | いつ | 中身（個人情報は入りません） |
| --- | --- | --- |
| `product_view` | 商品のページを開いた | `product_id`・`category_id`（主カテゴリー）・`tags` |
| `article_view` | ブログの記事を開いた | `article_id`・`blog`・`handle`・`author`（記事の「書いた人」の欄の文字）・`tags` |
| `page_view` | ショップのページを開いた | `page_id`・`handle` |
| `cart_add` | カートに入れた | `sku`（品番）・`quantity` |
| `cart_view` | カートを見た | `value_jpy` |
| `checkout_start` | 購入手続きを始めた | `value_jpy` |
| `purchase` | 購入を終えた（完了画面） | `order_number`・`value_jpy` |

どの行動にも `type` と `at`（ISO 8601）が付きます。**「何を見たか」はブラウザの申告**なので、本人なら偽れます（会員 ID は偽れません）。プラグインは、偽られても困らない範囲のアプローチにしてください（クーポンは 1 人 1 回にする、購入は注文の API で確かめる、など）。

## 許し方

1. プラグインのマニフェストに、欲しい行動を書いてもらいます（下の「プラグインを作る人へ」）。
2. 管理画面 → ショップ → プラグイン → hooks → その連携の画面に「お店の行動を渡す」の欄が出ます（モジュールが ON のときだけ）。
   欄が出ず「マニフェストを読めていません」と出るときは、登録したときにプラグインからマニフェストを取れていません。プラグインの URL をブラウザで開いて JSON が返ることを確かめ、連携の画面で「保存」を押すと読み直します（Cron でも 1 日 1 回読み直します）。
3. 渡す行動を選んで「設定を保存」。すべて外して保存すると、渡すのをやめます。変えてから効くまで最大 1 分かかります。

- 選べるのは、プラグインが求めた行動だけです。プラグインがマニフェストを変えて求める範囲を狭めたら、渡すときも狭い方になります（広げても、運営者が許し直すまで広がりません）。
- 許しを変えたことは、組織の監査ログに残ります。

## 送り方（Banto を経由する）

```
お店の画面（Banto のスクリプト）─┐
                                  ├→ Banto（/<ショップ>/_x、ヘッドレスは POST /api/shops/<ショップ>/events）
連携サイト（ヘッドレス）─────────┘        │ 会員は Cookie・会員トークンの署名で確かめる（DB に問い合わせない）
                                          │ 許された種類だけに絞って、署名して送る（応答の後で）
                                          ▼
                                     プラグイン（hooks の送信先の URL）
```

- お店の画面では、会員が見ているページにだけ小さなスクリプトが入ります。行動はブラウザでまとめて（20 件ごと・30 秒ごと・ページを離れるとき）、同じドメインの `/_x` へ送ります。外のドメインへ直接は送りません（広告ブロッカーに止められにくく、CSP も変わりません）。
- 1 回のまとまりは 16KB・50 件まで。同じ IP から 1 分に 120 回を超えると 429 です（回数は `RateLimitAdapter`。既定はメモリで、Workers では拠点ごとのゆるい上限です。確かにしたいときは WAF のレート制限を併用してください。docs/hardening.md）。
- プラグインが落ちていたら、その分は捨てます（行動の数だけ溜めることになるため、再送しません）。

### ヘッドレス

```http
POST /api/shops/<ショップ>/events
Authorization: Bearer <会員トークン>     ← 無ければゲスト（今の版では送りません）
Content-Type: application/json

{ "events": [ { "type": "article_view", "article_id": "coord-123", "author": "スタッフX", "tags": ["コーデ"] } ] }
```

- 204 を返します（送ったかどうかは返しません）。壊れた会員トークンは 401、モジュールが OFF のショップは 404 です。CORS は `*`。
- 連携サイトの読み物（外の CMS の記事）も、`article_view` に自分の ID と著者を付けて送れます。

## プラグインを作る人へ

マニフェスト（docs/hooks.md §4）に、欲しい行動を書きます。

```jsonc
"storefront_events": {
  "types": ["product_view", "article_view", "cart_add"],
  "visitors": "members"      // members（会員だけ）か all（ゲストも。今の版では会員だけが届きます）
}
```

届く形は hooks と同じ封筒で、イベント名は `storefront.events` です（署名の確かめ方も hooks と同じ。docs/hooks.md §3）。

```json
{
  "id": "…", "event": "storefront.events", "created_at": "…", "shop_id": "…", "attempt": 1,
  "data": {
    "customer_id": "…", "visitor": null, "source": "storefront",
    "events": [ { "type": "product_view", "at": "2026-11-04T10:15:02.000Z", "product_id": "…", "tags": ["秋"] } ]
  }
}
```

- 再送はありません（`attempt` はいつも 1）。届いた分を自分の保存場所（D1 など）に、期限を決めて置いてください。
- 会員の連絡先は載りません。送るときは AI 用 API（docs/ai-access.md）や LINE で送る口（docs/line.md §4）を使います。
- 退会（hooks の `customer.deleted`）で、その会員の分を消してください。
