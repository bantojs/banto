# 会員機能

購入者が会員になって、住所の保存・注文履歴・会員限定のクーポンを使える機能です。**既定は OFF**（ゲスト購入のみ）で、運営者が使うと決めたショップだけ有効にします。

- **アカウントはショップごと**です。同じメールアドレスでも、別のショップの会員とは別のアカウントになります（Shopify の顧客アカウントと同じ考え方）。
- ログインは、メールに届く **6 桁のコード** か **ログインのリンク** が基本です。ショップの設定で **パスワード** を、同梱モジュールで **LINE・Google でのログイン** を足せます（下の 3-2・3-3）。
- 会員の情報は、運営者自身の Supabase の `customers` に保存されます。Supabase の Authentication（ユーザー）は使いません（運営者の管理画面のログインだけに使います）。

設計の理由は docs/knowledge/10-members-identity.md。

## 1. 有効にする

1. 管理画面 → アップデートで、データベースの更新 `0012_member_auth` を適用します。
2. ショップ設定 → **プラグイン** → **メール通知** を有効にして、「送信元」を入れます（例: `マイショップ <no-reply@shop.example.jp>`。送り手で確認済みのドメインのアドレス）。送り手（Resend / 自分の SMTP サーバー / SendGrid / Amazon SES）は Cloudflare の「変数とシークレット」の `MAIL_TRANSPORT` で選びます（docs/email.md）。
   **ログインのコードのメールは、この送信元から送ります。** 注文確認のメールと同じ設定です。
3. ショップ設定の「会員」の欄で **「会員機能を有効にする」** をオンにして保存します。
   （管理画面の「会員」の画面や、クーポンの「ログイン中の会員だけ」から、この欄へのリンクが出ます）
4. ストアフロントのヘッダーに「ログイン」が出て、`/<ショップ>/account` で使えるようになります。

ログインのメールは、ショップ設定の「テーマ」のロゴとアクセントカラーを使った HTML で届きます（HTML を表示しないメールソフトには文字だけの版）。

Supabase の SMTP・メールのテンプレート・Redirect URLs の設定は、会員には **要りません**（運営者のパスワードの再設定のメールにだけ使われます）。

## 2. 会員から見た流れ

1. ログイン画面でメールアドレスを入れて「コードを送る」。
2. メールに「【ショップ名】ログインのコード：123456」が届きます。
3. 画面にコードを入れるか、メールの「ログインのリンク」を開いて「ログインする」を押します。リンクは別の端末（スマホでメールを開いた等）でも使えます。
4. 初めてのアドレスなら、この時点で会員登録になります（ログイン画面にプライバシーポリシーへのリンクを出しています）。

- コードとリンクの有効期限は 15 分、1 回限りです。コードを 5 回間違えると無効になり、送り直しになります。
- 同じアドレスへの送信は 15 分に 5 回・1 日 20 回まで（それを超えると送りません）。
- ログインは 30 日続きます（会員ページを開くたびに延びます。ただしログインした時点から最長 90 日）。会員ページの「すべての端末からログアウト」で、ほかの端末のログインも切れます。
- 会員ページの「ログイン中の端末」で、ログインしている端末（ブラウザと OS の名前、ログインした日時・最後に使った日時）を確かめ、心当たりのない端末だけをログアウトさせられます（数分以内に使えなくなります）。「ログアウト」もその端末のログインをサーバー側で取り消すので、Cookie を盗まれていても、ログアウトした後は使えません。データベースの更新 `0045_member_sessions` が要ります（当てると、それより前のログインは 1 回だけログインし直しになります）。

## 3. 運営者がすること

- **会員の一覧・削除**: 管理画面 → ショップ → 会員。削除すると、その会員はもうログインできません（注文は残ります）。
- **メールアドレスの変更**: 会員がメールアドレスを使えなくなったときの救済用です。会員の画面の「メールアドレスを変える」。変えると、その会員はすべての端末でログアウトし、**変更の前と後のアドレスに知らせのメール**が届きます。本人確認をしてから変えてください（パスワードが無いので、アドレスを変えられる人はその会員として入れます）。

## 3-2. パスワード（任意）

ショップ設定の「会員」の欄で **「パスワードでもログインできる」** をオンにすると、会員はマイページでパスワードを決めて、パスワードでもログインできます。

- メールのコードとリンクはいつでも使えます（パスワードを忘れたときの入口）。
- パスワードは 8 文字以上。照合はデータベースの中（bcrypt）で行い、Banto はパスワードそのものを保存しません。
- 同じアドレスで 15 分に 5 回、同じ回線から 1 時間に 30 回間違えると、しばらくパスワードでは入れなくなります（コードでは入れます）。
- パスワードを決め直すと、ほかの端末はログアウトします。
- **初めての端末からパスワードでログインすると、会員に知らせのメール**（「パスワードでログインしました」）が届きます。使い回しのパスワードで入られたときに、本人が気づけるようにするためです。同じ端末で前にログインしていれば送りません。データベースの更新 `0016_member_notice` が要ります。

## 3-3. LINE・Google でログイン（任意）

会員が LINE や Google のアカウントでログインできます（初回は会員登録）。ログイン中の会員は、マイページから連携・解除できます。
**設定はショップごと** です。同意画面には、そのショップで作ったアプリ（チャネル）の名前が出ます。

1. ショップ設定 → モジュール → **「LINE でログイン」** / **「Google でログイン」** を ON にします。
2. モジュールの「開く」で設定画面を開くと、**コールバック URL**（`https://<Banto の URL>/_oauth/line/callback` など。ショップに **独自ドメイン** を付けていれば `https://<ショップのドメイン>/_oauth/line/callback`）と手順が出ます。
   - **LINE**: [LINE Developers](https://developers.line.biz/) で「LINE ログイン」のチャネル（ウェブアプリ、名前はショップ名）を作り、コールバック URL を登録して公開します。チャネル ID とチャネルシークレットを設定画面に入れます。メールアドレスも受け取るなら「OpenID Connect」でメールアドレスの取得権限を申請します。
   - **Google**: Google Cloud のコンソールで「OAuth 同意画面」（アプリ名はショップ名、ユーザーの種類は外部、公開ステータスは本番）を作り、「認証情報」で OAuth クライアント ID（ウェブ アプリケーション）を作ってコールバック URL を承認済みのリダイレクト URI に登録します。クライアント ID とシークレットを設定画面に入れます。
3. 保存すると、ログイン画面にボタンが出ます（反映まで 30 秒ほど）。

- シークレットは、サイトの秘密（`SESSION_SECRET`）から作った鍵で **暗号化して** 保存します。画面には二度と出しません。`SESSION_SECRET` を変えたら、入れ直してください。
- 結びつける鍵は、それぞれのサービスの利用者 ID です。**確認済みのメールアドレス** が返ったとき（Google、メールの取得権限を申請した LINE）は、同じアドレスの会員と結びつきます。返らなければ別の会員（メールアドレスなし）になるので、既にいる会員はマイページの「連携する」で結びつけてください。
- メールアドレスの無い会員は、連携を外せません（入れなくなるため）。
- ショップに独自ドメインを付けた・変えたときは、LINE・Google に登録したコールバック URL も新しいドメインに変えてください（docs/custom-domain.md「ショップごとのドメイン」）。ログインのメールのリンクも、ショップのドメインになります。

## 3-4. パスキーでログイン（任意）

会員が、スマホやパソコンの **指紋・顔・PIN（パスキー）** でログインできます。パスワードと違って盗み見られず、偽のサイトでは使えません（パスキーはショップのドメインに結びつくため）。

- **独自ドメインを付けたショップだけ** で使えます（docs/custom-domain.md「ショップごとのドメイン」）。パスキーはドメインに結びつくので、Banto の URL にパスで並ぶショップ同士で同じパスキーの置き場を共有しないためです。
- ショップ設定 → モジュール → **「パスキーでログイン」** を ON にします。データベースの更新 `0046_mod_passkey` が要ります。
- 会員はマイページの「パスキー」で、使っている端末のパスキーを追加します。追加できるのは **ログインしてから 15 分以内** だけです（盗まれたログインでパスキーを足されないように）。過ぎていたら、画面の「コードを送る」でもう一度確かめてから追加します。追加すると、会員に **「パスキーを追加しました」のメール** が届きます。
- 次からはログイン画面の「パスキーでログイン」で入れます（メールアドレスを入れる必要もありません）。メールのコードもいつでも使えるので、パスキーの端末をなくしても入れます。
- 1 人 10 個まで。マイページの「パスキー」で消せます。「すべての端末からログアウト」ではパスキーは消えません。
- **ショップのドメインを変えると、それまでのパスキーは使えなくなります**（一覧に「使えません」と出ます）。会員はメールのコードで入って、追加し直します。
- 運営者は、管理画面 → 会員 →「操作」→ **「パスキーを全部消す」** で、その会員のパスキーを消せます。乗っ取られた会員の救済（メールアドレスの変更と一緒に）に使います。

## 3-5. 「お得な情報やセールの案内を受け取る」の同意（任意、0050）

ショップ設定 → 会員 の「レジと会員ページに『お得な情報やセールの案内をメールで受け取る』の欄を出す」を ON にすると、レジの配送先の画面と会員ページにチェックが出ます（既定は外れた状態。お客様が選んだときだけ同意になります）。

- 同意は会員の一覧（絞り込み・CSV）、AI 用 API（`marketing_consent`）、hooks の `customer.*` に出ます。**Banto 自身は案内メールを送りません。** 送るのはメール配信サービス（MA）で、その連携プラグインがこの同意を読みます（docs/ai-access.md §7）。
- ゲストの注文では、注文の行にだけ残ります（会員になったときには引き継ぎません）。
- 同意を**付けられるのは本人だけ**（レジ・会員ページ）。**外す**のは本人・運営者（会員の一覧の「案内メールの同意を外す」）・配信サービス（配信停止を API で書き戻す）のどこからでもできます。
- 文言（「お得な情報やセールの案内をメールで受け取る」）の適法性は、最終確認画面と同じく専門家に確認してください。日本では購入者や自分でアドレスを知らせた人への広告メールは同意の例外に当たりますが、配信サービス側や海外のお客様では明示の同意が求められます。

## 4. WooCommerce（WordPress）の会員を移す

同梱モジュール「WooCommerce から取り込み」で、顧客（権限グループ「顧客」）の **名前・メールアドレス・住所** を会員にできます（docs/woo-import.md「会員の取り込み」）。

- **パスワードも移せます**（任意。「パスワードでもログインできる」をオンにしたショップ）。WordPress のデータベースの `wp_users` 表を CSV で書き出して取り込むと、会員は WordPress と同じパスワードでログインできます（docs/woo-import.md「パスワードの取り込み」）。
  - 移せるのは **WordPress 6.8 以降の形式（`$wp$2y$…`）と bcrypt（`$2y$…`）だけ** です。古い形式（`$P$…`）は移しません。WordPress を 6.8 に上げても、保存済みのパスワードは本人が次にログインするまで古い形式のままなので、よくログインする会員ほど移せます。
  - 取り込んだパスワードは、初めてログインした時点で Banto の形式に保存し直します。180 日使われなかったものは消します。
  - 移せなかった会員は、ログイン画面でメールアドレスを入れれば、コードかリンクで入れます。
- **Banto からは会員にお知らせを送りません。** 切り替えの前に、運営者からお知らせのメールで案内してください。
  文面の例: 「サイトを新しくしました。これまでのパスワードでログインできます。うまくいかないときは、ログイン画面でメールアドレスを入れると、ログイン用のコードが届きます。」
- 取り込みは何度やり直しても重複しません。会員が自分で入れた名前・住所は上書きしません。
- 注文の履歴は移しません。

## 5. ヘッドレス（別のサイトの画面）で使う

連携側の画面からも、同じコードとリンク・パスワード・LINE・Google でログインできます（docs/headless.md「会員」）。Banto の API が会員のトークンを発行します。

## 6. 退会・削除

- 会員はマイページから退会できます（`customers` の行を消します。注文は残ります）。運営者は管理画面の「会員」から削除できます。
