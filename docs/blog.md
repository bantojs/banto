# ブログ（同梱モジュール）

「お知らせ」「読みもの」「スタッフブログ」のようなブログを作り、記事を新しい順に並べる同梱モジュールです（既定 OFF。0081_mod_blog の適用が必要）。

- **ブログ**は記事の入れ物です。お店がいくつでも作り（20 まで）、名前を決めます。`/<ショップ>/blogs/<ブログの名前>`（独自ドメインでは `/blogs/<名前>`）が記事の一覧です。
- **記事**はブログの中の 1 本です。`/blogs/<ブログ>/<記事の名前>` に出ます。日付・タグ・抜粋・アイキャッチ画像・書いた人を持ちます。
- 記事の本文と編集の画面は**ショップのページと同じ**です（決まった書式・ブロック・商品を並べる・ボタン・メディアライブラリ・予約公開・リビジョン・ゴミ箱。docs/pages.md）。**HTML は書けません**。
- 「ページ」（固定の情報）と「記事」（日付のある読み物）は分けています。記事には新しい順の一覧・ページ送り・タグ・RSS があり、ページにはありません。

## 1. 使い方

1. ショップ設定 → モジュール →「ブログ」を ON にします。ショップの管理画面に「ブログ」のタブが出ます。
2. 「新しいブログ」で名前（例: お知らせ）と URL の名前（例: `news`）を決めて作ります。ヘッダーかフッターのメニューにも出せます。
3. ブログの「新しい記事」で書きます。右の「ページの設定」の欄に、URL の名前・タグ（カンマか読点で区切る）・抜粋（一覧に出す短い紹介。空なら本文の頭）・書いた人があります。
4. 組織のスタッフに任せるときは、ページと同じ項目「ページ」（`content`）を割り当てます。

- 記事の一覧は 1 ページ 12 本、`?page=2` で次へ。`?tag=<タグ>` でタグの記事だけになります（検索エンジンには載せません）。並び順はブログの設定で決めます（下の「並び順とフィード」）。
- 一覧で読める深さは 1,200 本まで（それより古い記事は記事のページとサイトマップから届きます）。
- **RSS（Atom）**: `/blogs/<ブログ>/feed.atom` に新しい 20 本の題名・紹介・URL を出します（本文は載せません）。ブログの設定で出さないこともできます。
- 公開した記事とブログの一覧のページは、サイトマップ（`sitemap-pages.xml`）に載ります。
- 本文の書式と上限（表の列と行・囲みの深さ・HTML の大きさ）はページと同じです（docs/pages.md「書式」）。抜粋が空のときの紹介文は本文の頭から作りますが、長すぎる・入れ子のリンクは文字のまま残ります。
- 1 つのショップに記事は 5,000 まで。Banto をホスティングして貸す構成では、プランの上限 `plan_limits.articles` でこの Banto 全体の数も決められます。
- 「ブログを消す」と中の記事もすべて消えます（ゴミ箱には入りません）。記事だけを消すときはゴミ箱へ（30 日で自動で消えます）。
- 管理画面の JSON の書き出し（バックアップ）に入ります。

### 並び順とフィード（0116）

ブログの設定で、記事の並び順とフィードを決めます（メンテナの決定 2026-11-05。データベースの更新 `0116_blog_order` が当たるまで欄は出ません）。スタッフ紹介のような「お知らせではないブログ」を想定しています。

- **記事の並び順**: 新しい順（公開した日時、既定）・題の順・手で並べる。一覧（`/blogs/<ブログ>`、タグで絞った一覧、ブログの一覧のひな形）と、ページの「記事を並べる」ブロック（`::: articles`）の既定がこれに従います。ブロックだけ別の順にするときは `sort=new|title|manual` を書きます（docs/pages.md）。
- **手で並べる**: ブログの記事の一覧の画面に「順」の欄が出ます。数の小さい記事から並び（同じ数なら新しい順）、書き換えて「並び順を保存」を押します。新しい記事はそのブログの最後に入ります。並びを変えただけでは記事の更新日時は変わりません（サイトマップ・フィードの日時を動かさない）。0116 を当てた時点の記事には、今の新しい順で 1 から番号が振られます。
- **フィード**: 「フィード（RSS・Atom）を出す」を外すと、`/blogs/<ブログ>/feed.atom` は 404 になり、一覧と記事のページにもフィードのリンクを出しません。フィードはブログの並び順によらず、いつも新しい順です。
- ヘッドレスの API のブログには `article_order` と `feed_url`（出さないブログは `null`）が付きます（docs/headless.md）。

### 記事の項目（0117）

ブログごとに、記事に持たせる項目を決められます（メンテナの決定 2026-11-05。データベースの更新 `0117_article_fields` が当たるまで欄は出ません）。スタッフ紹介の身長・店舗、着こなしの書いた人・着用アイテムのように、**タグに入れていた「絞り込みではない情報」と「ほかの記事・商品・店舗へのつながり」**を項目で持ちます（タグは絞り込みのボタンに戻せます）。

- **決め方**: ブログの設定の「記事の項目」（AI 用 API なら `PATCH /api/v1/blogs/<ブログ>` の `article_fields`）に、1 行に 1 項目で「キー | 表示名 | 種類 | 補足」。20 項目まで。

  | 種類 | 値 | 補足 |
  | --- | --- | --- |
  | `text` | 文字（500 字まで） | — |
  | `number` | 数 | — |
  | `select` | 選択肢のどれか | 選択肢を `/` 区切りで |
  | `store` | このショップで使う実店舗 | — |
  | `product` / `products` | 商品の URL の名前（`products` はいくつも、24 まで） | — |
  | `article` / `articles` | 記事の URL の名前（`articles` はいくつも、24 まで） | 指すブログの URL の名前 |
  | `image` | このショップの画像の置き場の画像の URL（0120） | — |

  例: `height | 身長 | number`・`store | 店舗 | store`・`author | 書いた人 | article | staff`・`items | 着用アイテム | products`
- **値を入れる**: 記事の編集の画面の右の「ページの設定」に、そのブログの項目の欄が出ます（選択肢・店舗・指す記事は選ぶ。商品はカンマ区切りの URL の名前。画像は「画像を選ぶ」でブラウザで縮小して置くか、置き場の URL を貼る。ほかのサイトの画像は保存しません）。形と指す先（このショップにあるか）はデータベースが確かめ、合わなければ保存しません。定義に無い鍵・空の値は持ちません。
- **記事は公開の読み物なので、項目もすべて公開**です（お客様の画面・ヘッドレスの API に出ます）。秘密は書かないでください。
- **使い道**
  - 絞り込み: `::: articles blog=styling field:author=@article`（スタッフの紹介ページで「この人の着こなし」）、商品詳細のひな形で `::: articles blog=styling field:items=@product`（その商品を着た着こなし）。docs/pages.md「記事を並べる」
  - 記事の商品を並べる: 記事の本文やひな形で `::: products from=@field:items`（書いた順）
  - 記事のひな形の部品: `::: current part=field:<キー>`（値。店舗は名前、商品と記事は名前のリンク、画像は `<img>`）。キーが `author` で記事を指す項目があれば、`::: current part=author` は**指す記事の写真（アイキャッチ）・名前（題）・紹介（抜粋）・リンクのカード**になります（無ければ今までの「書いた人」の文字）
  - Liquid: `article.fields.<キー>`（値のまま。商品と記事は URL の名前、店舗は id）と `article.field_list`（`key`・`label`・`type`・`value`）。docs/themes.md
  - ヘッドレスの API: 記事に `fields`、ブログに `article_fields`（定義）
  - AI 用 API: 記事の保存（`POST /api/v1/blogs/<ブログ>/articles`）で `fields`、定義はブログの設定（`PATCH /api/v1/blogs/<ブログ>`、0118）の `article_fields`（docs/ai-access.md §9）
- 指す先の記事・商品の URL の名前を変えると、つながりは切れます（`::: products slugs=`・`tag=@product` と同じ）。

## 2. テーマ

- 既定のテーマ: 一覧（アイキャッチ・日付・題名・紹介、タグ、ページ送り、RSS のリンク）と記事を描きます。
- Liquid のテーマ: 一覧は `templates/blog`（ブログで選んだ名前があれば `blog.<名前>`）、記事は `templates/article`（記事で選んだ名前があれば `article.<名前>`）。渡すものは docs/themes.md の「使える名前」。テンプレートが無いテーマでは既定のテーマで描きます。
- 一覧の並びをショップのページで組むときは、ブログの一覧のひな形（0114、docs/pages.md「ひな形の割り当て」）を使います。記事の並び・タグで絞る・ページ送りは部品として置けます。
- 名前は Shopify の Liquid と同じ書き方（`blog.articles`・`article.content` など）です。コメントの機能はありません（`comments_enabled` は false）。

- 連携サイト: ヘッドレスの公開 API（`GET /api/shops/:shop/blogs`・`/blogs/:blog/articles`・`/blogs/:blog/articles/:article`）から一覧と本文（書式と描いた HTML）を読めます（docs/headless.md「ページ・ブログ」）。

## 3. 安全と速さ

- 本文はページと同じく、描くときに決まった形のタグだけの HTML にします（docs/pages.md §3）。
- お客様に見えるかは DB が決めます（公開中・公開の日時を過ぎた・ゴミ箱の外の記事だけ。RLS）。
- 一覧と記事はお店の画面の短いキャッシュに乗り、DB の往復は初めの 1 回で 4 回、2 回目からは 0 回です（`test/perf-budget.test.ts`）。
- お店の画面の使い方（docs/storefront.md）が「カートと購入だけ」「使わない」のショップでは、ページと同じく外のサイトへ回します。
