# 消費税（軽減税率）と領収書

Banto の価格はすべて **税込**（総額表示）です。消費税は「税率ごとの税込の合計」から 1 回だけ求めます（インボイス制度の決まり）。

## 1. 税率と商品の区分

- **商品ごと** に「税の区分」を選びます（商品の編集画面）。
  - 標準税率（既定 10%）
  - 軽減税率（既定 8%。飲食料品・新聞など）
  - 非課税・不課税（0%）
- 税率の数値と、消費税額の 1 円未満の端数の扱い（切り捨て・四捨五入・切り上げ。既定は切り捨て）は、ショップ設定の「送料・税・連絡先」で決めます。
- 送料は標準税率です。
- クーポンの値引きは、値引きした商品（と送料）の税率の対象額から差し引きます。どの商品の値引きか分からない古い注文だけ、税率ごとの合計の比で按分します。
- 注文には **確定した時点の税率** を残します（後で商品の区分や設定を変えても、過去の注文の領収書は変わりません）。

データベースの更新 `0017_tax` が要ります。適用するまでは、すべて標準税率として表示します（注文や表示は止まりません）。

## 2. 最終確認画面

税率ごとの対象額と消費税額（例: 「8% 対象 ¥2,160（うち消費税 ¥160）」）を出し、軽減税率の商品に「※」を付けます。ヘッドレス API の `confirmation.tax` にも同じ値が入ります（docs/headless.md）。

## 3. 領収書（同梱モジュール「領収書（インボイス対応）」）

1. ショップ設定 → モジュール →「領収書（インボイス対応）」を ON にします。
2. モジュールの画面で、発行者の名称（空ならショップ名）・**登録番号**（`T` + 13 桁）・但し書きを入れます。登録番号があれば「適格簡易請求書」として、無ければ「領収書」として出します。
3. 領収書を出せるのは、支払い済み・発送済みの注文だけです（キャンセル・返金済みは出しません）。
   - **購入者**: 「注文の確認」（注文番号とメールアドレス）の結果、または会員ページの注文履歴から。宛名は購入者が入れます。
   - **運営者**: 管理画面の注文の画面から（宛名の既定は購入者の名前）。
4. ブラウザの印刷で、紙か PDF にします（Banto はファイルを作りません）。

載る内容: 発行者の名称と登録番号、取引日、注文番号、品名（軽減税率の対象に ※）、数量・金額、送料・値引き、合計、**税率ごとの対象額（税込）と消費税額**、但し書き。住所は載せません。

注文確認・発送のメール（同梱プラグイン「メール通知」）にも、合計の下に税率ごとの対象額と消費税額が載ります（0022_tracking の適用前は、すべて標準税率として計算します）。メールは領収書ではありません。

## 4. 仕組み（開発者向け）

- 計算は `src/commerce/tax.ts` だけ（`taxBreakdown` / `orderTaxBreakdown`）。最終確認画面・領収書・管理画面が同じ関数を使う。
- `0017_tax.sql`: `products.tax_class`、`order_items.tax_rate`・`orders.shipping_tax_rate`・`orders.tax_rounding`（挿入のトリガーで入れる。確定の関数は触らない）、`lookup_order` に税率を足し、会員の注文 1 件を読む `member_order`、復元の後で区分と税率を戻す `restore_tax`。
- 領収書: `src/modules/receipt/`（データ取得なしで HTML を組む `render.tsx`、設定と運営者の画面 `admin.tsx`）。購入者の経路は `POST /<ショップ>/orders/receipt`（メールアドレスを URL に載せない）と `GET /<ショップ>/account/orders/<番号>/receipt`。
- バックアップからの復元では、明細の税率は戻した商品の区分から入れ直します（書き出した後で区分を変えていれば、書き出しの時点の税率とは違うことがあります）。
