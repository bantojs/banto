# 会員へのお知らせ

同梱モジュール「会員へのお知らせ」（`member_news`、0155、既定 OFF）を ON にすると、会員ページにお知らせが出ます。会員ごとに、どれを読んだか（既読）も覚えます。

Banto がするのは、**置かれたお知らせを出して、既読を覚えるところまで**です。だれに・いつお知らせを置くかは決めません。Banto が自分でお知らせを作ることもしません（試着の到着・期限の前日・クーポン・発送など）。

- 試着の状態とマイクーポンは、もともと会員ページに出ています。テーマはそこから印を作れます。
- それより先は、hooks を受けた外部プラグイン（MA など）が AI 用 API でお知らせを置きます。

## お知らせの種類

| 種類 | 置く人 | 出す相手 |
| --- | --- | --- |
| 全員向け | 管理画面（項目 marketing）・AI 用 API | 会員全員。会員の条件（同梱モジュール「会員の条件」が ON のとき。URL のパラメータを使う表示用の条件は使えない）で絞れる。お知らせに使っている条件は消せない |
| 1 人あて | AI 用 API | その会員だけ |

- 中身は、見出し（100 文字まで）・本文（文字だけ、1,000 文字まで）・リンク（任意）・出し始めと出し終わり（任意）です。
- リンクは `https://` で始まる URL か、お店の中のパス（`/products/tee` など。お店の URL の下に付きます）です。`\` と制御文字は使えません。
- 本文に HTML は書けません。描くときはエスケープします。
- 全員向けは 1 ショップ 100 件までです。
- 1 人あては、1 人・書き手（連携か運営者）ごとに 200 件までです。超えたら、その書き手が置いたものの古い順（置いた順）に消えます。ほかの書き手が置いたものは消しません。
- 会員を消すと、その人あてのお知らせと既読も消えます。

## 管理画面

「会員 → 会員へのお知らせ」で、全員向けのお知らせを書く・直す・消すことができます。

- 出し始めを未来にすると予約になり、出し終わりを過ぎると出なくなります。
- 外部プラグインが置いたお知らせは、ここでは直せません。消すことはできます。
- 1 人あてのお知らせは、件数だけが出ます。

## 会員ページ

- 既定のテーマは、会員ページの上に「お知らせ」の欄を出します。
  - 新しい順に 50 件までです。
  - まだ読んでいないものには印が付き、未読の数も出ます。
  - 「すべて既読にする」ボタンは `POST <ショップ>/account/news/read` に送ります。
- Liquid のテーマ（`templates/customers/account`）では、次の値が使えます。
  - `customer.news`: お知らせの並び。それぞれに `id`・`title`・`body`・`url`（そのままリンクにできる形）・`date`（ISO）・`date_on`（`2026-11-18`）・`read` があります。
  - `customer.news_unread_count`: 未読の数
  - `customer.news_read_url`: すべて既読にするとき POST する先

## ヘッドレス

会員トークン（`Authorization: Bearer bm1.…`）で、次の 2 つが使えます。

- `GET /api/shops/:shop/members/news`
  - 本人に見えるお知らせ（新しい順・50 件まで）と、未読の数 `unread` を返します。
  - `url` はお店の中のパスのまま返します（連携サイトで組み立ててください）。
- `POST /api/shops/:shop/members/news/read`
  - 既読にします。`{ ids: [...] }` で選ぶか（50 件まで）、何も付けなければ今見えるものすべてです。
  - 既読にした数を返します。

モジュールが OFF なら、どちらも 404 `module_disabled` になります。

## AI 用 API（外部プラグイン）

スコープは `member_news:write`（発行者に項目 marketing が要る）です。REST だけで、MCP には出しません。

- `POST /api/v1/member-news`: お知らせを置きます。
  - `{ customer_id?, title, body?, url?, starts_at?, ends_at?, audience_id? }`
  - `customer_id` があれば 1 人あてです（会員の条件は付けられません）。無ければ全員向けです。
- `GET /api/v1/member-news?customer_id=`: このトークンで置いたものを返します（新しい順・200 件まで）。
- `DELETE /api/v1/member-news/:id`: このトークンで置いたものを消します。

置いたものがだれのものになるかは、トークンで決まります。

- **連携に結んだトークン**（つないだプラグイン）: 置いたお知らせはその連携のものになります。触れるのは自分の連携のものだけです。連携を外すと、お知らせも消えます。
- **運営者のトークン**（連携に結ばない）: 触れるのは連携に結ばないもの（管理画面で書いたものを含む）だけです。

形が合わなければ 400 `invalid_member_news:<欄>`、モジュールが OFF なら 409 `module_disabled` を返します。

## しくみ

- 表は `member_news`（お知らせ）と `member_news_reads`（会員 × お知らせの既読）です。
  - 運営者が読めるのは、全員向けは項目 marketing、1 人あてと既読は項目 customers の人です（RLS。会員ごとの中身なので、お気に入りと同じ）。
  - 書けるのは関数だけです（`member_news_save`・`member_news_delete`・`api_member_news_*`）。
- 本人の読み取りと既読は service_role の `member_news_list`・`member_news_read` です。未読の数は見えるものすべてで数え、並べるのは新しい 50 件です。セッションの行と世代を確かめます。会員の条件の判定は DB の `banto_member_audience_ids` です。
- 会員ページを開いたときだけ読みます（お店のほかの画面では DB に問い合わせません）。モジュールが OFF なら読みません。
