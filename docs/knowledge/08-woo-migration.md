# 08. WooCommerce からの移行に向けた機能計画（2026-10-16）

運営者向けの手順は docs/woo-import.md。

「WooCommerce が遅くて困っている人」への移行提案に Banto を使うための計画。置き場所は 3 層の方針（docs/ARCHITECTURE.md「プラグインアーキテクチャ」、02-decisions.md）に従う。**ここに書いた層の振り分けと順番を変えるときは、先に人間に確認する。**

## 1. 振り分け

| 候補 | 層 | 理由（判定基準の番号は ARCHITECTURE.md） |
| --- | --- | --- |
| カテゴリー（階層）・ブランド・SKU の選択肢（サイズ / 色）・JAN / GTIN・セール価格 | コア | (2) 商品データの基本。フィード・インポーター・テーマの前提 |
| カスタム項目（WooCommerce の ACF 相当） | コア（器だけ） | (2) 項目定義と値の保存だけ。使い方はテーマとモジュールが決める。**任意のコードは動かさない**（宣言して入力する形まで） |
| 値引き・送料・税の計算 | コア（拡張点） | (1) quote の照合を 1 か所に保つ |
| クーポン | 判定と回数はコア、登録画面は同梱モジュール | (1)(3) 判定は `discounts.ts`、回数は在庫と同じ予約の流れで原子的に数える。Stripe には Banto が決めた額のクーポンを付ける（方式 A）。09-coupons.md |
| 商品フィード（Google Merchant / Meta）+ JSON-LD | 同梱モジュール | (3)(4) 読み取り出力。Cron で生成して R2 に置き、URL を各サービスに登録してもらう。API キーを預からない |
| WooCommerce インポーター | 同梱モジュール | (3) 移行時だけ使う。CSV の解析はブラウザ側、Worker には小分けで送る |
| 送り状 CSV（ヤマト B2 / 佐川 e飛伝） | 同梱モジュール | (3)(4) Shift_JIS への変換はブラウザ側 |
| 配送日時の指定 | 同梱モジュール | (1)(3) 配送の拡張点 |
| 軽減税率（8% / 10%）とインボイスの領収書 | 税率はコア、領収書は同梱モジュール | (1) 税率は金額の判定。領収書の生成はブラウザ側（印刷 / PDF 保存） |
| URL リダイレクト（WordPress ごと置き換える場合） | 同梱モジュール（インポーターの一部） | (3) |
| Meta / Google への API 即時同期、CRM、レビュー | 外部プラグイン | (5) |
| 海外配送 | 後回し（配送の拡張点は国を受け取れる形にしておく） | 通貨・住所形式・関税・税制までコアに及ぶ。単独で設計書から |
| 定期購入 | 後回し | 注文・在庫の設計に大きく関わる。単独で設計書から |

移行提案で最初に伝える制約: (1) 任意のコードは動かせない（カスタム項目は宣言型、独自処理は hooks / 外部プラグイン） (2) WordPress のパスワードは移せない。会員（名前・メール・住所）は REST API で取り込み、会員はメールのコードかリンクで入る（2026-10-16、0012。パスワードは第 2 段階で bcrypt の形式だけ移す。docs/members.md）。

## 2. 順番

1. 土台: 速度の予算の検査（DB 往復回数のテスト、Worker サイズの上限）、モジュールの ON/OFF の仕組み（**どちらも済、2026-10-16**）
2. 商品マスタの拡張（コアの器）（**済、2026-10-16、0008_catalog**）+ WooCommerce インポーター（**CSV 方式・REST API 方式とも済、2026-10-16、0009 + 同梱モジュール woo_import**。対応付けは 02-decisions。CSV の本番確認済み、REST API は実機未確認）
3. 値引きの拡張点 + クーポン（**判定型は済、2026-10-16、0010 + 同梱モジュール coupons**。配布型・自動発行・取り込みが続き。09-coupons.md）
4. 商品フィード + JSON-LD
5. 配送の拡張点 + 配送日時の指定、軽減税率 + 領収書、送り状 CSV
