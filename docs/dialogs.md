# お店の画面のダイアログ（同梱モジュール dialogs）

お店の画面に、条件に合うお客様だけにお知らせを出します。ゲストにも出せるので、LINE やメールが届かないお客様にも、**お店を見ている「熱いうち」に**案内できます。

- 既定は OFF です。管理画面 → ショップ → モジュール →「お店の画面のダイアログ」を ON にし、「開く」でダイアログを作ります（データベースの変更 `0110_mod_dialogs` が要ります。API とプラグインからは `0111_dialogs_api` も）。扱えるのは項目「マーケティング」を持つ人です。
- **決められるのは「今の訪問・今のページで分かること」だけ**です（下の表）。過去の閲覧や購入の履歴でお客様を選ぶ・何日か待って出す・効果を集計する、は MA のプラグインの仕事で、Banto は持ちません。
- **Banto は何も溜めません。** 回数（1 回の訪問に 1 回・閉じたら n 日出さない）は、お客様のブラウザが覚えます。

## 作れるもの

| 項目 | 中身 |
| --- | --- |
| 出し方 | 下のバー（スマホにおすすめ）・中央のダイアログ（背景を暗くする）・角の小窓 |
| 見出し・本文 | 文字だけ（本文は 500 字まで、改行はそのまま）。HTML は書けません |
| 画像 | https:// の URL を 1 枚 |
| ボタン | 2 つまで。リンクは https:// か、ショップの中のパス（`/p/tee` など） |
| クーポンコード | クーポンのモジュールで作った公開のコード。お客様は「コピー」できます。使える回数・1 人 1 回などは、クーポンの決まりで縛ってください |
| 期間・優先 | 始まりと終わり。同じページで重なったら優先の高いもの 1 つだけ |

色と角の丸みは、テーマの CSS の変数で変えられます: `--banto-dialog-bg`・`--banto-dialog-text`・`--banto-dialog-accent`・`--banto-dialog-accent-text`・`--banto-dialog-radius`。

## だれに・どのページで・きっかけ

| | 選べるもの |
| --- | --- |
| だれに | すべて・ゲストだけ・会員だけ・会員の条件（同梱モジュール「会員の条件」、docs/audiences.md） |
| どのページで | すべて・トップ・商品のページ・商品の一覧と検索・ブログ・ページ・カート。商品（スラッグ）・カテゴリー（主カテゴリー）・タグを入れると、どれかに合う商品・記事のページだけ |
| きっかけ | ページを開いて n 秒後・n % まで読んだ・離脱しそう（パソコンでマウスが画面の上へ出たとき）・今回の訪問で n ページ見た・カートの合計が n 円以上（カートの画面を一度見た後から） |

- きっかけは、入れたものがすべてそろったときに出します。何も入れなければ、ページを開いてすぐです。
- **レジ（配送先・最終確認）・会員ページ・注文照会・試着・お問い合わせには出しません**（特定商取引法の最終確認と、個人情報の画面に重ねないため）。
- 「今回の訪問」は、最後にお店の画面を開いてから 30 分以内の続きです。
- Liquid のテーマでも出ます（`content_for_header` に入ります）。

## 出した・閉じた・押した

ダイアログを出した・閉じた・ボタンを押した、は次の 2 か所へ渡ります。Banto は数えません。

- **GA4**（同梱モジュール GA4、docs/ga4.md）: イベント `banto_dialog_view`・`banto_dialog_close`・`banto_dialog_click`（`dialog_id`）。
- **お店の行動を連携に渡す**（docs/event-relay.md）: 行動の種類 `dialog_view`・`dialog_close`・`dialog_click`（`dialog_id`）。連携ごとに許したときだけ。

## 気をつけること

- **見せかけの操作で出されても困らないものだけを渡してください。** きっかけはお客様のブラウザが判定するので、本人なら出させることも、出させないこともできます。案内・公開のクーポン（使える回数を Banto が縛る）は大丈夫です。1 人だけの特別な値引きは、ダイアログではなく、会員なら LINE などで渡してください。
- **スマホで開いてすぐ全画面を覆う出し方**は、検索エンジンに嫌われることがあります。スマホでは「下のバー」か、数秒後に出すのがおすすめです。
- クーポンや「今だけ」の見せ方は、景品表示法（二重価格・有利誤認など）に気をつけてください。運営者の責任です。
- 閉じるボタンは必ず出ます。キーボード（Esc）でも閉じられ、読み上げのソフトにはダイアログとして伝わります。

## API とプラグインから（0111）

管理画面のほか、AI 用 API（スコープ `dialogs:write`、docs/ai-access.md §14）と、つないだ外部プラグイン（MA など）からも作れます。

```http
POST /api/v1/dialogs
Authorization: Bearer banto_...
Content-Type: application/json

{ "name": "カゴ落ち", "title": "カートに商品が残っています", "body": "今日中なら送料無料です", "layout": "bar",
  "audience": "all", "pages": { "kinds": ["product", "list"] }, "trigger": { "exit_intent": true, "cart_min_jpy": 1 },
  "buttons": [{ "label": "カートを見る", "url": "/cart" }], "snooze_days": 3 }
```

- 鍵は管理画面の欄と同じです（`name`・`enabled`・`priority`・`layout`・`title`・`body`・`image_url`・`buttons`・`coupon_code`・`audience`・`audience_id`・`pages`・`trigger`・`snooze_days`・`starts_at`・`ends_at`）。`pages.products` と `pages.categories` は id で渡します。
- **プラグインが作ったダイアログは、その連携のもの**です。管理画面の一覧に「連携「…」が作ったもの」と出ます。運営者はそこで止めたり消したりできます（プラグインが後から書き直すことはあります）。連携を外すと消えます。
- プラグインに作らせるには、プラグインのマニフェストの `scopes` に `dialogs:write` を入れ、「つなぐ」で運営者が許します（docs/hooks.md §6）。
- 履歴（過去の購入・閲覧）でお客様を選びたいプラグインは、会員の独自項目に写してから（`customers:write`）、その条件の「会員の条件」をダイアログの「だれに」に使います。ダイアログ自体は、今の訪問・今のページで分かることだけで出します。
